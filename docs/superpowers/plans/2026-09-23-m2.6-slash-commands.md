# M2.6 Slash Commands Implementation Plan

> **Execution:** task by task. Tests are written with each change and run once, in Task 10 (global rule `## Tests` in `~/.claude/CLAUDE.md`). Build and commit follow the rule in force when this starts (in M2.5 the user asked for one compile at the end, and commits only when asked). This plan gives decisions, files, public interfaces, required behavior and the tests to write. It does not carry the code: the implementer writes it.

**Goal:** Typing "/" at the start of the message box lists the commands the conversation's agent announced over ACP (built-in commands, skills, the repository's custom commands, MCP prompts); choosing one runs it or completes it with its argument hint.

**Source of truth:** `docs/superpowers/design/2026-09-23-slash-commands.html`. Open it in a browser. It holds the interactive mock and every requirement (`ACP-01`…`ACP-04` protocol, `KIT-01`…`KIT-03` model and pure logic, `CMD-01`…`CMD-07` UI, `TITLE-01`, `A11Y-02`). The ACP requirements quote the adapters Rocky installs (claude-agent-acp 0.81.0, ACP SDK 1.5.0, OpenCode 1.18.32). When the mock and a requirement's text disagree, the text wins.

**Architecture:** No new ACP request: commands arrive as `available_commands_update` notifications and run as ordinary prompts whose text starts with `/name`. RockyKit turns the notification into a `SessionEvent`, keeps the list per `ChatSessionModel`, caches the last list per repository and agent, and adds two pure pieces (`SlashQuery`, `SlashCommandFilter`) plus a title rule. RockyUI adds a popup over the message box, driven by the composer's text view.

**Spec:** `docs/superpowers/specs/2026-09-22-rocky-design.md` (agents over ACP). M2.5 (the shell): `docs/superpowers/plans/2026-09-23-m2.5-sidebar-topbar.md`.

## Decisions

Taken with the user on 2026-09-23:

- **Only the agent's own commands**, as ACP announces them. No Rocky command palette and no per-repository commands in Rocky (`OUT-20`).
- **Its own milestone**, with this plan and its HTML, not inside M2.5 or M3.

Taken in this plan. Change them here, not during implementation:

- **Trigger only at the very start of the message** (`KIT-02`): both adapters only treat a prompt as a command when its first text starts with "/", and a "/" mid-text is usually a path.
- **Replace, never merge,** the list on every update (`ACP-01`), per conversation.
- **In-memory cache per repository and agent** (`KIT-01`) so a new conversation has a list while its agent starts; not persisted.
- **Return runs commands without input, completes commands with input; Tab always completes** (`CMD-04`).
- **Insert names exactly as announced** (with `mcp:`); the adapter rewrites them (`ACP-02`, `ACP-03`).
- **Tiered filtering** (prefix, segment, substring, description) rather than fuzzy scoring (`KIT-03`): predictable with hundreds of skills.
- **A command never names a conversation** (`TITLE-01`).
- **The popup is an overlay, not a window,** and the text view keeps focus (`CMD-01`, `CMD-03`).

### Task 1: Receive the command list

**Requirements:** `ACP-01`, `ACP-02`, `ACP-04`, `KIT-01`.
**Files:** `Sources/RockyKit/ACP/ACPProtocol.swift`, `Sources/RockyKit/Chat/SlashCommand.swift` (new), `Sources/RockyKit/Chat/ChatSessionModel.swift`, `Tests/RockyKitTests/ACPProtocolTests.swift`, `Tests/RockyKitTests/ChatSessionModelTests.swift`, `Tests/RockyKitTests/Fixtures/fake-acp-agent.sh`.

```
public struct SlashCommand: Equatable, Sendable, Identifiable { name; description; inputHint: String?; isMCP }
SessionEvent: + case availableCommands([SlashCommand])
ChatSessionModel
  public private(set) var commands: [SlashCommand] = []
  public private(set) var commandsReceived = false
```

It must:
- Parse `available_commands_update` per `KIT-01`'s rules (drop entries without a name, empty description allowed, `input.hint` or nil, order kept, `_meta` ignored).
- Replace `commands` on every event and set `commandsReceived`.
- Install the notification handler before sending `session/new`, `session/load` or `session/resume`, since both adapters send the list from a `setTimeout` right after the response. Confirm it in the code; fix the order if needed.
- Teach the fake agent to send an `available_commands_update` immediately after its `session/new` result, and again on demand.

Tests:
- `ACPProtocolTests.parsesAvailableCommands` (Claude shape with hint, null input, an `mcp:` name) and `parsesOpenCodeCommandsWithoutInput`; replace the M1 test that expected `.ignored("available_commands_update")`.
- `ChatSessionModelTests.commandsSentRightAfterSessionNewArrive`, `commandsAreReplacedNotMerged`.

Commit `feat(kit): receive the agent's slash commands`.

### Task 4: Popup model and key routing

**Requirements:** `CMD-03`, `CMD-04`.
**Files:** `Sources/RockyUI/SlashCommandPopup.swift` (new, model part), `Sources/RockyUI/Composer.swift`.

```
@MainActor @Observable final class SlashCommandPopupModel {
  var isOpen: Bool; var query: String; var matches: [SlashCommandFilter.Match]; var selection: Int
  var dismissedToken: String?
  func update(text: String, caret: Int, firstIsAttachment: Bool, commands: [SlashCommand], confirmed: Bool)
  func moveSelection(_ delta: Int)
  enum Choice { case send(String), complete(String, hint: String?) }
  func choose(isReturn: Bool) -> Choice?
}
```

It must:
- Be owned by `ComposerController`; re-run `update` on every text or selection change of the text view.
- In `ComposerTextView.keyDown`, before today's Return and ⇧Tab handling: while open, ↑/↓, Return, Tab and Esc go to the model; never while `hasMarkedText()`.
- Esc must reach the popup first. Since M2.5, Esc during a turn cancels it in `ChatView`'s key monitor, which runs before the text view sees the key and skips only for `MenuPresenter.open`, `SettingsPresenter.shared.isPresented` and an `attachedSheet`. Add the popup's open state to those conditions, so Esc with the popup open closes it and does not cancel the turn. Manual check: during a turn, type "/", press Esc: the popup closes and the turn keeps running.
- Apply a `Choice`: replace the first token with "/name" (send) or "/name " (complete, caret after the space), keeping the attachments and the text after the token; show the ghost hint until the next keystroke (`CMD-04`).
- Return with no match falls through to today's send.
- `.send` goes through today's send, so during a turn it lands in M2.5's message queue (a queued row after "Working"; it goes out when the turn ends). The popup does not special-case a running turn. Manual check: during a turn, pick `/compact` with Return: it shows as queued and runs after the turn.

Commit `feat(ui): route composer keys to the slash command popup`.

## Known risks

- **The handler race** (Review Focus 1): if `ChatSessionModel` installs its handler after `session/new` returns, the first list is lost until the next change. Task 1 checks the order.
- **UTF-16 offsets:** `NSTextView` ranges are UTF-16; the U+FFFC attachment markers and emoji make Swift `String` indices differ. Keep `SlashQuery` in UTF-16 offsets end to end.
- **Large lists:** a user with many skills can have hundreds of commands; rank off the main thread only if Task 2's 5 ms budget fails.
- **Adapter drift:** the unsupported-command list, the `mcp:` rename and local-only commands belong to claude-agent-acp 0.81.0; a newer adapter may change them. Rocky shows whatever is announced, so only the chip and title rules depend on the list.
