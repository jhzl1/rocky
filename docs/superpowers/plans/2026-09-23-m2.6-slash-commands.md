# M2.6 Slash Commands Implementation Plan

**Status: done**, merged into `development` on 2026-09-23 (`0f88959`) and pushed. Task 9, the check with real agents, is still open: `docs/superpowers/m2.6-verification.md`.

> **Execution:** task by task. Tests are written with each change and run once, in Task 10 (global rule `## Tests` in `~/.claude/CLAUDE.md`). Build and commit follow the rule in force when this starts (in M2.5 the user asked for one compile at the end, and commits only when asked). This plan gives decisions, files, public interfaces, required behavior and the tests to write. It does not carry the code: the implementer writes it.

**Goal:** Typing "/" at the start of the message box lists the commands the conversation's agent announced over ACP (built-in commands, skills, the repository's custom commands, MCP prompts); choosing one runs it or completes it with its argument hint.

**Source of truth:** `docs/superpowers/design/2026-09-23-slash-commands.html`. Open it in a browser. It holds the interactive mock and every requirement (`ACP-01`…`ACP-04` protocol, `KIT-01`…`KIT-03` model and pure logic, `CMD-01`…`CMD-07` UI, `TITLE-01`, `A11Y-02`). The ACP requirements quote the adapters Rocky installs (claude-agent-acp 0.81.0, ACP SDK 1.5.0, OpenCode 1.18.32). When the mock and a requirement's text disagree, the text wins.

**Architecture:** No new ACP request: commands arrive as `available_commands_update` notifications and run as ordinary prompts whose text starts with `/name`. RockyKit turns the notification into a `SessionEvent`, keeps the list per `ChatSessionModel`, caches the last list per repository and agent, and adds two pure pieces (`SlashQuery`, `SlashCommandFilter`) plus a title rule. RockyUI adds a popup over the message box, driven by the composer's text view.

**Spec:** `docs/superpowers/specs/2026-09-22-rocky-design.md` (agents over ACP). M2.5 (the shell): `docs/superpowers/plans/2026-09-23-m2.5-sidebar-topbar.md`.

## Decisions

Taken with the user on 2026-09-23:

- **Only the agent's own commands**, as ACP announces them. No Rocky command palette and no per-repository commands in Rocky (`OUT-20`).
- **Its own milestone**, with this plan and its HTML, not inside M2.5 or M3.

Taken in this plan. Change them here, not during implementation:

- **Trigger only at the very start of the message** (`KIT-02`): both adapters only treat a prompt as a command when its first text starts with "/", and a "/" mid-text is usually a path.
- **Replace, never merge,** the list on every update (`ACP-01`), per conversation.
- **In-memory cache per repository and agent** (`KIT-01`) so a new conversation has a list while its agent starts; not persisted.
- **Return runs commands without input, completes commands with input; Tab always completes** (`CMD-04`).
- **Insert names exactly as announced** (with `mcp:`); the adapter rewrites them (`ACP-02`, `ACP-03`).
- **Tiered filtering** (prefix, segment, substring, description) rather than fuzzy scoring (`KIT-03`): predictable with hundreds of skills.
- **A command never names a conversation** (`TITLE-01`).
- **The popup is an overlay, not a window,** and the text view keeps focus (`CMD-01`, `CMD-03`).

public struct SlashCommand: Equatable, Sendable, Identifiable { name; description; inputHint: String?; isMCP }

### Task 4: Popup model and key routing

**Requirements:** `CMD-03`, `CMD-04`.
**Files:** `Sources/RockyUI/SlashCommandPopup.swift` (new, model part), `Sources/RockyUI/Composer.swift`.

```
@MainActor @Observable final class SlashCommandPopupModel {
  var isOpen: Bool; var query: String; var matches: [SlashCommandFilter.Match]; var selection: Int
  var dismissedToken: String?
  func update(text: String, caret: Int, firstIsAttachment: Bool, commands: [SlashCommand], confirmed: Bool)
  func moveSelection(_ delta: Int)
  enum Choice { case send(String), complete(String, hint: String?) }
  func choose(isReturn: Bool) -> Choice?
}
```

It must:
- Be owned by `ComposerController`; re-run `update` on every text or selection change of the text view.
- In `ComposerTextView.keyDown`, before today's Return and ⇧Tab handling: while open, ↑/↓, Return, Tab and Esc go to the model; never while `hasMarkedText()`.
- Esc must reach the popup first. Since M2.5, Esc during a turn cancels it in `ChatView`'s key monitor, which runs before the text view sees the key and skips only for `MenuPresenter.open`, `SettingsPresenter.shared.isPresented` and an `attachedSheet`. Add the popup's open state to those conditions, so Esc with the popup open closes it and does not cancel the turn. Manual check: during a turn, type "/", press Esc: the popup closes and the turn keeps running.
- Apply a `Choice`: replace the first token with "/name" (send) or "/name " (complete, caret after the space), keeping the attachments and the text after the token; show the ghost hint until the next keystroke (`CMD-04`).
- Return with no match falls through to today's send.
- `.send` goes through today's send, so during a turn it lands in M2.5's message queue (a queued row after "Working"; it goes out when the turn ends). The popup does not special-case a running turn. Manual check: during a turn, pick `/compact` with Return: it shows as queued and runs after the turn.

Commit `feat(ui): route composer keys to the slash command popup`.

## Known risks

- **The handler race** (Review Focus 1): if `ChatSessionModel` installs its handler after `session/new` returns, the first list is lost until the next change. Task 1 checks the order.
- **UTF-16 offsets:** `NSTextView` ranges are UTF-16; the U+FFFC attachment markers and emoji make Swift `String` indices differ. Keep `SlashQuery` in UTF-16 offsets end to end.
- **Large lists:** a user with many skills can have hundreds of commands; rank off the main thread only if Task 2's 5 ms budget fails.
- **Adapter drift:** the unsupported-command list, the `mcp:` rename and local-only commands belong to claude-agent-acp 0.81.0; a newer adapter may change them. Rocky shows whatever is announced, so only the chip and title rules depend on the list.

## Changes during implementation

Record here anything that differs from this plan, with the date and the reason.

- **2026-09-23, the first list after `session/new` (Task 1).** The handler was already installed before
  `session/new`, but `ChatSessionModel.receive` dropped every update while `sessionId` was nil, and the list comes
  right after the response, so keeping it depended on actor scheduling. Now the last `available_commands_update`
  that arrives while `sessionId` is nil is kept and applied when the id is stored (`adopt(sessionId:)`, for both
  `session/new` and `session/load`); every other update before the id is still dropped. Command lists are applied at
  once, not buffered while the conversation is hidden, so the cache stays current. Fake agent: a "too early" text
  before the `session/new` result (it sent an empty command list there), the list right after `session/new` and
  `session/load`, `FAKE_ACP_COMMANDS_EARLY`, and the prompt "change commands". The M1 `.ignored` test now uses
  `user_message_chunk`. Pinned by `ChatSessionModelTests.commandsSentRightAfterSessionNewArrive`,
  `commandsThatBeatTheSessionIdAreKept`, `commandsAreReplacedNotMerged`,
  `aResumedSessionGetsItsCommandsWithoutReplayingHistory`.
- **2026-09-23, parsing (`KIT-01`).** Besides the listed rules: an empty name is dropped, a name announced twice keeps
  its first entry (the popup identifies rows by name), and a blank hint counts as none, so Return runs that command.
  Pinned by `ACPProtocolTests.parsesAvailableCommands`.
- **2026-09-23, `SlashCommandFilter` (`KIT-03`).** The HTML's `rank(_:query:) -> [SlashCommand]` and the plan's
  `[Match]` both exist: `rank` returns commands, `matches(_:query:)` returns `Match` with `nameRange` in `Character`
  offsets. The first version used Foundation's case-insensitive search and took about 3 ms per ranking of 300
  commands in a debug build under the parallel suite, over the budget for two rankings; `SlashCommand` now keeps its
  name and description lowercased from its init, and the filter searches bytes with `memmem`. Pinned by
  `SlashCommandFilterTests`.
- **2026-09-23, when the popup is open (`KIT-02`).** Read as: open while the caret is inside the first token; text
  after the token does not close it by itself. `CMD-07` opens the popup in front of existing text, and `CMD-04` keeps
  "the text after the token", so arguments can follow an open token ("/review 12" with the caret at 3 gives "re").
  A file badge ends the token like whitespace. Pinned by `SlashQueryTests`.
- **2026-09-23, choosing (`CMD-04`).** Return on a command without a hint sends "/name" plus any text after the token,
  as the requirement says, where the mock completes instead. The ghost hint shows only when nothing follows the
  completed name, as in the mock. Tab with the popup open and no match does nothing rather than typing a tab. A
  message brought back with ↑ from the history closes the popup on its token, so ↑ and ↓ keep browsing until the
  token is edited. Manual check.
- **2026-09-23, the "+" menu entry (`CMD-07`).** An empty message gets "/"; a message with text gets "/ " before it,
  with the caret after the "/", so its first word stays out of the token a chosen command replaces; a message that
  already starts with "/" gets the caret after it. Manual check.
- **2026-09-23, titles (`TITLE-01`).** While a conversation's list is unknown (no list of its own and none cached,
  as at launch), a message whose first token is "/name" counts as a command. The backfill in
  `AppModel.reloadConversations` runs before any agent starts and would otherwise title a command-only conversation
  "/compact" at the next launch, and a title never changes. The backfill now walks the conversation's user messages
  (`store.messages`) for the first one that is not a command, instead of `firstUserMessage`. Pinned by
  `RecordsTests.titleWithAnUnknownListSkipsEveryLeadingSlashName` and
  `AppModelTests.firstNonCommandMessageNamesTheConversation`.
- **2026-09-23, where the UI reads the list.** `ChatView` has no `AppModel`: `WorkspaceDetailView` passes
  `model.commands(for: chat)` into it, and the chip (`CMD-06`) checks the same list as the popup, the conversation's
  own or the cached one. The popup's rows are a `LazyVStack`: their height is fixed, so nothing is estimated (the chat's
  plain-`VStack` rule is about estimated heights).

- **2026-09-23, the popup opens on its first row.** User report: the list rendered from the bottom. The chat's
  `ScrollView` has `.defaultScrollAnchor(.bottom)`, and the popup, which floats in its bottom inset, inherited it
  through the environment, so it opened scrolled to the end. `SlashCommandList` sets `.defaultScrollAnchor(.top)` on
  its own scroll view. On the manual checklist.

- **2026-09-23, terminal commands like Conductor (`CMD-08`, new requirement).** User decision: "hazlo igual que
  conductor". Claude Code's terminal-only commands answer over ACP with one line ("Use /mcp in the terminal for
  details"); Conductor never sends them and offers an embedded terminal instead, and Rocky now does the same. What was
  built, beyond `CMD-08`'s text:
  - **The list** is `TerminalOnlyCommand` (`SlashCommand.swift`), fixed and Claude-only: mcp, agents, hooks, memory,
    permissions, plugins. A message runs one when its first token is "/name" with a name on the list ("/mcp extra"
    yes, "/mcpx" and "/mcp:linear:triage" no, never in OpenCode). What follows the token goes with it, on one line,
    file badges left out.
  - **Never reaching the agent** is enforced in RockyKit: `ChatSessionModel.send` and `enqueue` drop a terminal
    command, so no path (idle, starting, mid-turn, the queue, Send Now, a popup pick) delivers it. `ChatView.send`
    asks `chat.terminalCommand(in:)` first, after `takeMessage()` has emptied the box, files included, and shows the
    strip. A popup pick with Return or a click goes through that send.
  - **The popup's list** comes from `AppModel.commands(for:)`, which applies `TerminalOnlyCommand.offered`: an
    announced one gets "(opens terminal)" and loses its input hint, so Return opens the terminal instead of
    completing it (the mock's rule); the ones the agent did not announce come after its own, with Conductor's
    descriptions. Nothing is added while no list is known, so "Starting Claude Code…" stays.
  - **`KIT-03` tier 0**: an exact name ranks first, or "/mcp" and Return picked an mcp:linear:triage announced
    before it.
  - **The terminal** (`AppModel.openEmbeddedTerminal(conversationId:command:)`, `embeddedTerminal(conversationId:)`,
