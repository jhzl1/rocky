## Decisions

1. **The tab is a third kind of center tab.**
   - `AppModel` gains `allChangesTabs: Set<String>` (workspaces with the tab open) and `selectedAllChanges:
     Set<String>`.
   - A workspace shows at most one of a file tab, a diff tab or All changes on top of its conversation. Every setter
     of `selectedFiles` and `selectedDiffTabs`, and `showConversation`, drops the workspace from
     `selectedAllChanges`; `openAllChanges` clears the other two.
   - `ConversationTabs` draws the tab after the diff tabs. `chatArea` draws `AllChangesView` on top of the
     conversation, as it draws a diff tab.
   - The workspace cleanup clears both sets and the fold state.
2. **GIT-01:** `showsChanges(workspaceId:)` also holds while `selectedAllChanges` contains the selected workspace
   (`ALL-09`).
3. **The fold state lives in `AppModel`, in memory:** `allChangesStates: [String: AllChangesState]` (`ALL-05`).
   - `AllChangesState` (RockyKit, `KIT-21`) holds:
     - `folded: Set<String>`;
     - `expandedGaps: [String: Set<DiffGap>]`;
     - `shownLarge: Set<String>`;
     - `current: String?` (`ALL-06`);
     - `hunkStarts: [String: [Int]]`, the new starts the expanded runs were made for.
   - `AllChangesState.reconciled(with: WorkspaceChanges)` is pure. It forgets files no longer in the list, and the
     expanded runs of files whose hunk starts moved. It runs when `changes[workspaceId]` is set.
   - Methods: `openAllChanges`, `closeAllChanges`, `toggleAllChangesFold(path:)`, `setAllChangesFolded(_:)`,
     `expandAllChangesGap(path:gap:)`, `showAllChangesLarge(path:)`, `stepAllChangesFile(step:)`.
4. **`KIT-21` returns sections, not a flat list.** One pinned `Section` per file needs its header apart from its rows.
   This departs from the design's `[[AllChangesRow]]`; record it.
   - The call is `AllChangesLayout.sections(changes:state:newLines:) -> [AllChangesSection]`, where `newLines` holds
     the worktree lines that are loaded, by path.
   - An `AllChangesSection` has:
     - `path`;
     - `caption: (kind, count)?`, on the first file of Uncommitted or Committed;
     - `header`: the file, folded or not, whether it can fold, and its note;
     - `rows: [AllChangesRow]`: `.line`, `.gap`, `.caption(text, action)` or `.spacer`.
   - Ids are `"\(path)|\(DiffRow.id)"`, `"\(path)|caption"`, `"\(path)|spacer"`, `"\(path)|header"` and
     `"section|uncommitted"`. A file added above leaves every other id as it was.
   - `AllChangesLayout.anchor(in:was:previousPaths:)` resolves an anchor that is gone. It takes the same file's
     nearest line by the number in the id, else the header of the next file of `previousPaths` still listed, else
     the last file; nil when there are none.
   - The captions and notes are `ALL-07`'s texts, from the file alone. A binary file's sizes come in as a
     parameter, since the kit reads no git here.
5. **Each file loads when its header first appears.**
   - The load is `UnifiedDiffView.load()`'s, moved into a shared `DiffFileLoader` that both views use, so the diff tab
     stays as it is: the worktree lines, the widest line, the tokens, and a binary file's sizes.
   - `AllChangesView` keeps one loader result per path, keyed by the `FileDiff` it was made for. A file that changed
     loads again when it shows.
   - The width is the widest among the unfolded files. A file not loaded yet counts its hunks only,
     `DiffMetrics.maxColumns(file:lines: nil)`.
6. **Sideways scroll with pinned headers (dev-2's flagged risk).** One `ScrollView([.horizontal, .vertical])` holds a
   `LazyVStack(pinnedViews: .sectionHeaders)`. Each header is `viewportWidth` wide inside `Sticky`, so it stays at the
   left edge as the code scrolls. Task 3 checks this first with `screencapture`. If a pinned header and `Sticky`
   don't work together, stop and tell dev-2 and the user before clipping any line; that is a design change.
7. **The scroll position (`ALL-09`)** is `.scrollPosition(id: $anchor, anchor: .topLeading)` on the stack's
   `.scrollTargetLayout()`.
   - After each change of sections, an anchor that is gone becomes `AllChangesLayout.anchor(...)`.
   - Check in Task 3 that this keeps the sideways offset. If it resets it, restore `scroll.x` after the move.
8. **Keys (`ALL-06`).**
   - `ChangedFileCommands` calls `stepAllChangesFile` when All changes is the selected tab, and
     `showAdjacentChangedFile` otherwise.
   - The view scrolls the current file's header to the top on each step, from a serial in the state.
   - Return opens the current file's diff tab, through an `onKeyPress` on the focused list.
   - No ⌘F: a diff tab in Diff mode has none today (only the editor's find bar), so "as in a diff tab" means none.
     Record it, and tell dev-2.
9. **The button (`ALL-01`)** goes in `ChangesHeadRow`, before "⋯": `RockyTextButtonStyle`, 24 points, with
   `rectangle.stack`. It is disabled with no files, and calls `openAllChanges`.
10. **Part B.**
    - `LinkAttachments.reviewComments(number:markdown:)` names the file `[GITHUB]-PR-<n>-comments.md`.
      `Kind.reviewComments(Int)` is checked before `.pullRequest`.
    - `FileBadge` shows `text.bubble` and the tooltip "Review comments on #<n>", from the path alone.
    - `AgentPrompts.reviewCommentsMessage(number:count:)` builds `RVW-02`'s two texts.
    - `sendComments` writes the file with `writeLinkAttachment`, then sends the short message with it.
      `markCommentsAdded` stays where it is.

## Global constraints

- `CLAUDE.md`'s UI standards: Rocky's menus and dialogs, `Font.rocky`, `Zoom.shared`, `Theme` colors, `.clickable()` on
  every custom button, and no scroll bar track.
- Energy: nothing loads for a folded file or a file not scrolled to. No timer. The diff is computed only under
  `showsChanges`.
- No animation for arriving files (`ALL-09`). The fold chevron turns in 150 ms (`Theme.Motion.state`), and rows appear
  at once.

## Known risks

- Decision 6: pinned headers inside a two-axis scroll view with `Sticky` offsets.
- Decision 7: `scrollPosition(id:)` in a two-axis scroll view may move the sideways offset.

  toolbar's count and Collapse all keep a long list readable.

## Changes during implementation

2026-09-29:

- **The keys go through the view.** `stepAllChangesFile` records an `AllChangesStep` (the step and a serial) in
  `allChangesSteps`. The view picks the next file, from the current one or else from the file at its top, with
  `WorkspaceChanges.file(after:step:)`. The model never learns the scroll position, so scrolling writes no model
  state.
  - A scroll by hand (`onScrollPhaseChange`, `interacting`) clears `current`, so the next press starts from the top
    file.
- **The top row survives a tab switch.** `allChangesAnchors`, not observed, is written when the view goes and read
  when it comes back, so the tab reopens where it was (`ALL-02`). The view is not kept alive behind other tabs.
- **`AllChangesCaption` is an enum.** It has `large`, `binary`, `modeOnly`, `renamed` and `emptyFile`, and the view
  writes the text, because a binary file's sizes are read by the view. An added empty file gets "Empty file", as in
  its diff tab.
- **Reused as they are:**
  - `ChangesSectionHeader` and `ChangesEmptyState` (made internal) for the kind captions and `ALL-08`;
  - `WorkspaceTab` gained `detail` for the file count;
  - `DiffFileLoader` is `UnifiedDiffView.load`'s reading, now shared.
- **`RVW-01`, a fallback:** if the comments file cannot be written, `sendComments` sends the full text as before,
  rather than nothing.
- Tests:
  - `AllChangesLayoutTests` (5);
  - `AppModelTests.allChangesTabOpensFoldsAndKeepsItsDiffComputed`;
  - `AppModelTests.addAllSendsEveryPendingCommentInOrder`, now checking the file;
  - `AgentPromptsTests.reviewCommentsMessageCountsTheCommentsSent`;
  - `LinkAttachmentsTests.reviewCommentsHaveTheirOwnFile`.
- **Queued messages, added to M3.1 at the user's request** ("siento que la ubicación de los botones de enviar y
  editar no es la mejor"). The user picked "Debajo, siempre visibles" among three options.
  - Each queued message has a line under it, right-aligned and always visible: its status ("Queued", "On hold until
    your next message", "Goes when the agent is ready"), then Send now, Edit and × as 11.5 text buttons, lit on
    hover.
  - It replaces the hover actions at the bubble's left and the group's one `QueueCaption`, which is gone.
  - `QueuedMessagesView.swift`, `ChatView`, the guide's "Mensajes en cola" and `CLAUDE.md`'s chat rule changed.
  - UI only, so no test; it goes on the manual checklist.
- **Pasting an image alone did nothing** (user report: an image on the clipboard pasted only after picking it again in
  a clipboard manager). The message box is a rich-text `NSTextView` without `importsGraphics`, which enables Paste
  only for text types. A screenshot app leaves only image types, so ⌘V never reached `paste(_:)`. Raycast adds the
  file's path as text, which is why it worked through it. `ComposerTextView` now enables Paste whenever
  `PastedAttachments.canRead` (a file URL or an image, checked from the types alone). UI only; it goes on the manual
  checklist.

After the merge, 2026-09-30:

- **A conversation lost its unsent text** when another conversation or workspace took the screen (user report).
  - Why: each conversation has its own `ChatView` (`.id(ObjectIdentifier(chat))`), and the box's text lived in its
    `@State`.
  - Now `ComposerController.lastDraft`, updated on every change, goes to `AppModel.keepDraft` as the view goes. It
    comes back through the `pendingDrafts` / `takePendingDraft` path the model menu's moves already use.
  - An empty box forgets it, a closed conversation keeps none, and AGM-03's move leaves no copy behind
    (`movedDrafts`).
  - Tests: `AppModelTests.aConversationKeepsItsDraftWhileAnotherIsOnScreen`, and
    `aPickWithMessagesOpensANewConversationAndLeavesTheOldOne` extended.
