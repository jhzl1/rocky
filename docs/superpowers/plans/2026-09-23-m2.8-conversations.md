## Decisions

These come from the code map of 2026-09-25, where the design assumes something the code does not have.

1. **The draft moves through the model for both paths.** The draft type is `MessageHistory.Entry`, which holds text,
   files and the line chip. The design's `ComposerDraft` (text, attachments) has no chip.
   - `AppModel.pendingDrafts[conversationId]` is read once by the next `ChatView` for that conversation.
   - AGM-03 needs this because it moves the draft to another conversation.
   - AGM-02 needs it too: `WorkspaceDetailView` keys the chat view by the chat's identity, so a rebuilt chat gets a new
     `ChatView` and its `@State` composer.
2. **AGM-02 swaps the chat in one step, with no gap.** Today `makeChat` returns the existing chat for an id, and it
   awaits the environment and the launch. On an agent's first use it may install OpenCode. If the old chat left
   `chats` first, the tab would show "Opening the conversation…" and the menu would lose its button. So `switchAgent`
   works in this order:
   1. builds the new chat, awaiting everything, without registering it;
   2. writes the record (`agent`, `acpSessionId` = nil) and reloads the conversations;
   3. stops the old chat and puts the new one in `chats` on the same main-actor turn;
   4. starts it.
3. **Stopping during a start keeps "Stopped".** `performStart`'s failure path must not overwrite a `.stopped` state.
   Otherwise stopping an agent that is still starting (AGM-02 step 1) reports a spurious failure.
4. **The open menu looks the chat up by conversation id.** `MenuButton` captures its content when it opens, so the
   content must never hold a `ChatSessionModel`. It reads `model.chat(conversationId:)` on every body. The menu's id
   is `"model-\(conversationId)"` (`AGM-02`).
5. **`pickModel` says what it did.** It returns `.setModel` (same agent), `.switchedInPlace` (AGM-02) or
   `.openedConversation` (AGM-03). The view closes the menu only for the last, because the model cannot reach the
   presenter.
6. **The menu stays open after a pick.** Model rows use `PanelRow`, which does not dismiss. `pick` stops calling
   `presenter?.dismiss()`. Esc, a click outside, sending, and AGM-03 close the menu. `ChatView.send` dismisses an open
   model menu of its conversation.
7. **The rail touches the menu's left edge.** `MenuButton`/`MenuPanel` gain an option for no content padding, with the
   panel's clip shape. Every other menu is unchanged.
8. **Motion tokens as the design gives them.** `Theme.Motion` gains:
   - the 200 ms ease-out appear;
   - the 120 ms ease-in disappear;
   - the 150 ms cross-fade;
   - the 180 ms ease-out slide.
   
   Options change inside RockyKit, so the view uses `.animation(_:value:)` on the options, not `withAnimation`.
   `Theme.Motion.enter` stays as it is.
9. **The label leaves "Default" out** (`AGM-07`): the button reads "Opus 5.5 High", or "Opus 5.5" when the effort is
   the agent's default.
10. **The catalog lives next to the database:** `RockyPaths.agentModels`, `agent-models.json`. Tests build it in a
    temporary directory, like `ciLogs`.
11. **⌃` goes through the model** (`KBD-04`). The panel selection is view state that a menu command cannot reach. So
    the command bumps `AppModel.terminalToggleRequests[workspaceId]`, a serial, and `WorkspaceDetailView` acts on it.
    It owns `panelSelection` and `terminalPanelCollapsed`, and it focuses the terminal through a focus request that
    `TerminalHostView` honors while already on screen.
    - Before the toggle, `window.firstResponder is TerminalView` inside the bottom panel means "a terminal has the
      keyboard". The embedded slash-command terminal (`.embeddedTerminal`) is not the bottom panel.
    - Giving the keyboard back goes to the selected tab: the composer through `ComposerController.focus()`, or the
      file or diff tab's editor.

### Task 1 (the catalog)

- **Every new list of models reaches the catalog**, through `ChatSessionModel.onModelOption`, called from
  `configOptions`' `didSet` whenever the `model` option's choices change: `session/new`, `session/load`,
  `config_option_update`, and also a `session/set_config_option` answer, since it carries the whole list. A change of
  the current model alone reports nothing. Claude's list goes under the Claude instance the chat started with. Pinned by
  `ChatSessionModelTests.eachNewListOfModelsIsReported`, `aResumedSessionReportsItsModels` and
  `AppModelTests.aSessionsModelsReachTheCatalog`, `claudesModelsAreKeptUnderTheRepositorysInstance`.
- `AppModel.modelCatalog` is public to read and observed, and `AppModel.knownModels(agent:workspaceId:)` resolves the
  repository's Claude instance for the menu. An empty `claudeConfigDir` is the default instance. A failed write keeps
  the list in memory. Pinned by `AgentModelCatalogTests`.
- The fake agent reports its options on `session/load` too, and a prompt "add a model" announces a longer list in a
  `config_option_update`.

### Task 2 (switching and opening)

- **`pickModel` and `switchAgent` take the draft** (`draft: MessageHistory.Entry? = nil`): `KIT-11`'s signatures have
  none, and Decision 1 moves the draft through the model on both paths. `newConversation(workspace:agent:)` became
  `newConversation(workspace:agent:model:draft:)` with defaults, so its callers stay. Pinned by
  `AppModelTests.aPickInAnEmptyConversationSwitchesItInPlace` and `aPickWithMessagesOpensANewConversationAndLeavesTheOldOne`.
- **`pickModel` returns `ModelPick?`**: nil when nothing happened (the conversation is gone, or the new chat could not
  be made, with `errorMessage`), so the view neither closes the menu nor reads a failure as a pick. `switchAgent`
  returns whether it switched (discardable). Not pinned.
- **`pendingModel` is a `SessionConfigOption.Choice`**, not a value: the toast names the model ("GPT-5.5"), which its
  value does not. The name comes from the conversation's own options, else the catalog, else the value itself. Pinned by
  `ChatSessionModelTests.aPendingModelTheAgentDoesNotHaveKeepsItsDefault` and
  `AppModelTests.aPickedModelTheAgentDoesNotHaveKeepsItsDefault`.
- **The pending model is set before the agent is ready**, in `performStart` once the session's options arrive, so the
  button never shows the default first; a pick made during that round trip is set after it. A pick of the
  conversation's own agent while it starts or is stopped waits in `pendingModel`. Pinned by
  `ChatSessionModelTests.thePendingModelIsSetOnceWhenTheOptionsArrive` and `AppModelTests.aPickOfTheSameAgentSetsTheModel`.
- **Decision 3 covers the successful start too**: a start that finishes after a `stop()` terminates its process, stays
  "Stopped" and never calls `onSessionReady`, so the old agent's session id cannot reach the record the switch cleared.
  A `stop()` before the process runs lets the start run to its end, so this path is the common one. Pinned by
  `ChatSessionModelTests.stoppingWhileStartingStaysStopped`.
- **`startInBackground` checks the state again in its task**: `start()` takes a stopped chat for a Restart, so a chat
  replaced before its background start ran (AGM-02, at once after "+") would have started an agent nobody stops. Pinned
  by `AppModelTests.aSwitchStopsAnAgentThatIsStillStarting`.
- **The switch reads the record again after building**, and gives up if a message went out meanwhile, the tab closed,
  or a later pick took over (`agentSwitches`, one token per conversation). The swap registers the new chat, then calls
  the old chat's `stop()`, whose state changes before its first suspension, so both happen on one main-actor turn.
  Pinned by `aPickInAnEmptyConversationSwitchesItInPlace` (it watches `chats` through the whole switch) and
  `aSwitchStopsAnAgentThatIsStillStarting` (two switches in a row).
- **The switch closes the conversation's embedded terminal** (CMD-08): it runs the old agent's Claude Code command, and
  the new chat's view never shows it. Not pinned.
- `MessageHistory.Entry.isEmpty`: an empty draft is not kept in `pendingDrafts`.

### Task 3 (the rail and the menu)

- **The draft reaches the menu through `ConversationComposers`** (RockyUI, `Composer.swift`): each conversation's
  message box by conversation id, held weakly, registered by `ChatView` on appear. The menu captures its content when
  it opens and outlives the `ChatView` a switch rebuilds, so it looks the box up at each pick, as it looks up the chat
  (Decision 4). It copies the draft (`ComposerController.draft`) and never empties the box: a failed pick leaves the
  draft where it was, and a successful one takes the box away with its view (the rebuilt view of AGM-02, the tab
  switch of AGM-03). UI, on the manual checklist.
- **`ChatView` takes `model`, `workspaceId` and `conversationId`**, for the menu and to take the pending draft once as
  it appears, after that update, so the message box's text view exists.
- **The rail's items have their own style** (`AgentRailItemStyle`), not `RockyIconButtonStyle`, which `AGM-01`'s SwiftUI
