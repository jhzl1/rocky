## GitHub account per process

```
active account: jhzl1
with GH_TOKEN: ocampos-biai
git https without GH_TOKEN: ok (repo visible to the active account; pick a repo it cannot see)
git https with GH_TOKEN: denied
ssh identity: Hi ocampos-biai! You've successfully authenticated, but GitHub does not provide shell access.
```

`GH_TOKEN` overrides `gh`'s active account for both `gh` and git over HTTPS. Evidence: active account is `jhzl1`; with `GH_TOKEN` set to an `ocampos-biai` token, `gh api user` resolves to `ocampos-biai`; `git ls-remote` of the private repo `jhzl1/sinkro` succeeds without `GH_TOKEN` set and is denied with it set.

The "ok" result without `GH_TOKEN` comes from `gh auth git-credential` answering with the active account, not from an `osxkeychain` credential cache. `~/.gitconfig` sets an empty `credential.https://github.com.helper` (which resets the helper list, dropping the system `osxkeychain`) followed by `!/opt/homebrew/bin/gh auth git-credential`.

SSH: `ssh -F /dev/null -i ~/.ssh/id_rsa_celes -o IdentitiesOnly=yes -T git@github.com` returns `Hi ocampos-biai!`. `-F /dev/null` is required because `~/.ssh/config`'s `Host github.com` entry adds `id_rsa_personal`, which would otherwise be tried first (or instead).

## Env isolation: `CLAUDE_CONFIG_DIR` leak

The probe run against Claude Code inherited `CLAUDE_CONFIG_DIR=/Users/jhzl/.claude-celes` from the launching shell, so `claude-agent-acp` loaded that Claude instance's hooks. Their text (`UserPromptSubmit says: CRITICAL FIRST ACTION ...`) leaked into `agentText`, ahead of the actual probe value (`rocky-11FE3F96`).

Consequence: Rocky must set `CLAUDE_CONFIG_DIR` explicitly per repo (bound the same way as the GitHub account), never inherit it from the launching environment. The user has multiple Claude instances (`~/.claude`, `~/.claude-celes`, `~/.claude-rentek`) and Rocky needs to pick one per repo rather than pass through whatever the app process happened to have set.

## Xcode toolchain gap

Only Command Line Tools are installed on this Mac (`xcode-select -p` → `/Library/Developer/CommandLineTools`). XCTest and swift-testing are unavailable under Command Line Tools alone, so the M0 spike used an executable test runner (`swift run acp-probe-tests`) instead of XCTest.

Consequence: M1 (SwiftUI app + XCTest per spec Section 5) requires installing full Xcode. This is the user's decision, not something M1 can route around.

## stderr as a debug channel

OpenCode's and Codex's ACP adapters both wrote empty stderr logs (0 lines) during these runs. Only Claude Code's adapter produced stderr output, and it was post-result teardown noise, not diagnostic content about the request itself. Debugging OpenCode and Codex issues must rely on JSON-RPC protocol messages (requests, responses, error payloads), not stderr.

## Consequences for M1/M4

- `gh auth git-credential` honors `GH_TOKEN` for git over HTTPS (verified with `git ls-remote`; `git push` uses the same credential helper but was not exercised) — Section 2's env-injection design (`GH_TOKEN`, `GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_NAME/EMAIL`) stands as designed.
- All three ACP adapters (`opencode acp`, `claude-agent-acp@0.81.0`, `codex-acp@1.13.0`) advertise `session/load` in `initialize`; M1 can plan to use ACP resume for all three agents, pending a real resume test.
- `claude-agent-acp` (the M0 unknown originally named it `claude-code-acp`) does pass process `env` to agent tools (proven with a live probe value round-tripped through the shell tool); OpenCode is proven the same way. Codex is unverified because the auth failure happened before the shell tool ran — this needs re-verification in M1 once a Codex credential (API key or ChatGPT login) is provisioned.
- New: Rocky must bind `CLAUDE_CONFIG_DIR` per repo alongside the GitHub account, and must use `GIT_SSH_COMMAND="ssh -F /dev/null -i <key> -o IdentitiesOnly=yes"` (the `-F /dev/null` flag, not just `-i`/`-o IdentitiesOnly=yes`) to bypass `~/.ssh/config` host aliases that would otherwise pick the wrong key.
- New: M1 needs a Codex login decision (API key vs ChatGPT) before Codex can be used at all, and the env-reaches-tools probe for Codex must be re-run once that credential exists.
- New: M1's SwiftUI app + XCTest plan (spec Section 5) has a prerequisite — full Xcode must be installed; Command Line Tools are not enough.
