Rocky · Updates (M5)

At launch, and when it becomes active again, at most once a day, Rocky asks GitHub for its latest release. A newer one shows a banner above the sidebar's footer: Update downloads it, replaces /Applications/Rocky.app and relaunches, after asking with a mini-modal when agents, scripts, tasks, terminals or unsaved edits would stop. Rocky ▸ Check for Updates… and Settings do the same on demand. Try it: "New version", then Update; turn on "Things running" or "Download fails" first to see those paths.

Knowing about a new version

UPD-01

The check

Technical
Asks
GET https://api.github.com/repos/jhzl1/rocky/releases/latest over URLSession, without a token (the repository is public; the user's GitHub accounts are never sent), Accept: application/vnd.github+json. It reads tag_name ("v0.3.0"), html_url, and the asset named Rocky.zip (browser_download_url, size). releases/latest already skips drafts and prereleases.
Newer
The tag, without its "v", compared as numbers part by part (0.10.0 is newer than 0.9.0) with CFBundleShortVersionString. A release without a Rocky.zip asset counts as no update.
When
On events, never on a timer (CLAUDE.md: "Nothing polls at rest. No timers on the disk or the network"): at launch, and whenever Rocky becomes active again (NSApplication.didBecomeActiveNotification), each time only when the last check is more than 24 h old; the time of the last check in UserDefaults. The agents' check works the same way (AppModel.checkAgentUpdates, called at launch). Plus the manual check (UPD-06). GitHub allows 60 requests an hour without a token; at most one a day is far under.
Where
Only a Rocky running from /Applications/Rocky.app checks and updates itself. A build run elsewhere (build/Rocky.app, swift run) never shows the banner, and Settings' row says why (UPD-06), so a development build is never replaced by a release.
Quiet
The daily check shows nothing when it finds nothing or fails: no toast, no badge. Only the manual check answers either way.
UPD-02

The banner

In scope
Where
In the sidebar, right above its footer (SB-06, "Add repository" and Settings), full width with 8 of margin at the sides and below. The workspace list shrinks to make room, so nothing in the window moves, and the banner stays out of the conversation. With the sidebar hidden, it is hidden too; Settings and the Rocky menu still offer the update (UPD-06).
Look
Radius 10, fillControl with a 1 px hairline ring (on the sidebar's opaque color), padding 10, 10, 10, 12, gap 8 between its two lines. Line 1: arrow.down.circle 14 in accent; "Rocky 0.3.0 is available" 12.5 textPrimary, with "You have 0.2.0" under it (11.5 textTertiary); a 16 pt × at the right (xmark 9, textTertiary, tooltip "Hide until the next launch"). Line 2: "What's new ↗" (12 textSecondary, opens html_url in the browser), then at the right Update: 24 pt, radius 6, white fill with #111316 text (DLG-02's primary).
Motion
It enters with M2.5's entrance (220 ms, from 6 pt below, fade) and leaves with the reverse, 150 ms. Reduce Motion: it just appears and goes.
Hide
× hides it until Rocky's next launch. A newer version found meanwhile brings it back at once. The next launch shows it again for the same version, so an update is never forgotten for good. Nothing is stored beyond the launch.
Access
VoiceOver reads "Rocky 0.3.0 is available. You have 0.2.0." with the actions Update, What's new and Hide.
Done when
With 0.3.0 released, a Rocky 0.2.0 in /Applications shows the banner at launch; × hides it until the next launch; the workspace area never moves.

Updating

UPD-03

Update while things run

In scope
Asks
Updating relaunches Rocky, which stops everything, as quitting does. So when something would stop, Update first shows a mini-modal (M2.8 DLG-02); with nothing, it goes straight on. Title "Update to Rocky 0.3.0?", message "Rocky relaunches, and these stop:" then a list, one line each, at most 5 lines and then "and 3 more":
  • "2 agents working: tokyo, lima" (their turns are cancelled; the conversations stay);
  • "The Run script in oslo", "2 tasks: Run: API + Web, Run: Admin";
  • "3 terminals", "The Setup script in porto";
  • "2 files with unsaved edits: openapi.ts, README.md".
Idle conversations and finished processes are not listed: nothing of theirs is lost.
Buttons
Cancel · Update and Relaunch (primary, default). With unsaved edits, the quit prompt's three (DLG-05): Don't Save (destructive, left, ⌘D) · Cancel · Save All and Update (primary); a save that fails cancels the update and shows that file, as when quitting.
Blocked
While a workspace is being created, set up or removed (M2.9 WSC-01, WSC-07), Update is disabled, tooltip "Wait for lima to finish setting up": a relaunch in the middle would leave a half-made or half-deleted worktree.
Done when
With an agent working and a file unsaved, Update asks with the three buttons and both listed; with nothing running it downloads at once.
UPD-04

Downloading, installing, relaunching

In scope
States
The banner shows each state in place; its size barely changes.
StateLine 1Line 2
Downloadingspinner 14 · "Downloading Rocky 0.3.0…"a 3 pt bar (fillButton track, accent fill, radius 2) and "6.2 of 15.1 MB" (11 mono textTertiary, tabular); Cancel as a text button. No ×.
Installingspinner 14 · "Installing Rocky 0.3.0…" · "Rocky relaunches in a moment"none; nothing is clickable
FailedUPD-05UPD-05
Order
  1. The zip downloads to ~/Library/Caches/Rocky/Updates/0.3.0/ (URLSession download task, its progress feeding the bar). Rocky keeps working meanwhile; the mini-modal's stops happen only at step 3.
  2. It unzips with ditto -x -k and checks the new app before anything is replaced: codesign --verify --deep --strict, the same certificate as the running Rocky ("Rocky Local", compared by its leaf certificate), CFBundleIdentifier equal, and the version equal to the tag. Any mismatch is a failure; nothing is installed.
  3. Rocky stops everything as quitting does (stopAllProcesses, the agents' turns cancelled), starts a detached helper (/bin/sh -c) and quits. The helper waits for Rocky's process to end, moves the old /Applications/Rocky.app aside, moves the new one in, removes the old one, and opens the new one; if the move fails, it puts the old one back and opens it.
After
The new Rocky, on its first launch, shows one toast: "Updated to Rocky 0.3.0" with What's new (the release page). It knows by comparing its version with the last one it ran (UserDefaults).
Cancel
Cancel during the download stops it, deletes the partial file and brings the banner back to "is available".
Done when
From 0.2.0, Update shows the bar moving to 15.1 MB, then "Installing…", Rocky closes and opens as 0.3.0 within seconds with the "Updated" toast, and /Applications/Rocky.app is 0.3.0.
UPD-05

When it fails

In scope
Banner
Line 1: exclamationmark.triangle 14 in danger, "Couldn't update to 0.3.0" and the reason under it (11.5 textTertiary, up to 2 lines, the full text in the tooltip); the × comes back. Line 2: "Copy install command" (a text button: copies the curl … | bash line, toast "Copied the install command") and Retry (primary).
Reasons
"No internet connection" · "GitHub answered 503" · "The download stopped at 6.2 of 15.1 MB" · "The new app isn't signed like this one" (UPD-04 step 2) · "Rocky can't write to /Applications". Nothing is replaced in any of them, and Rocky keeps running as it was.
Retry
Starts at UPD-04's step 1 again. The install command is the way out when retrying keeps failing, for example without write access to /Applications.

On demand

UPD-06

Check for Updates, and the version

In scope
Menu
Rocky ▸ Check for Updates…, right under About Rocky, where macOS apps keep it. While it checks, it reads "Checking for Updates…" and is disabled.
Answers
Nothing newer: toast "Rocky 0.2.0 is the newest version". Newer: the banner (UPD-02), shown even if × hid it; with the sidebar hidden, also a toast "Rocky 0.3.0 is available" with Update. A failure: toast "Couldn't check for updates: reason".
Settings
A "Rocky" section first in Settings, one row, like the agents' "Updates" row (SettingsView): "Version", detail "0.2.0 (build 12) · checked today at 9:41". At the right: "Up to date", or Update to 0.3.0 (the same flow as the banner), or the download's state, and "Check Now" with a 12 pt spinner while it checks. Outside /Applications, the detail reads "0.2.0 (build 12) · runs from build/, so it doesn't update itself" and there is no button.
Done when
Check for Updates… on the newest version shows "is the newest version"; Settings shows the version and the last check.

RockyKit

KIT-20

Rocky's own updates

Technical
struct RockyRelease { version: String; pageURL: URL; zipURL: URL; zipSize: Int }
enum RockyUpdates {
  static func parse(latestRelease: Data) throws -> RockyRelease?   // nil without a Rocky.zip asset
  static func isNewer(_ tag: String, than current: String) -> Bool // "v0.10.0" > "0.9.0"
  static func stops(running: RunningWork) -> [String]              // UPD-03's lines, at most 5 + "and N more"
  static func helperScript(old: URL, new: URL, pid: pid_t) -> String
}
// AppModel
var rockyUpdate: RockyUpdateState   // .none, .available(RockyRelease), .downloading(done, total), .installing, .failed(reason)
func checkRockyUpdate(manual: Bool) async
func updateRocky() async

Tests: parse on a trimmed real answer, with and without the asset; isNewer for equal, patch, minor, "v" prefix and 0.10 against 0.9; stops for each kind, the plural forms and the cap; the helper script's text (waits for the pid, moves aside, restores on failure). The download, the signature check and the relaunch are on the plan's manual checklist, against a real release.
