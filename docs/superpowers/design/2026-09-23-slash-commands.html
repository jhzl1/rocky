What the agents send and expect (ACP)

ACP-01

Receiving the command list

Technical

Agents announce their commands with a session/update notification whose update is available_commands_update. Schema (ACP SDK 1.5.0, AvailableCommandsUpdate):

{ "jsonrpc": "2.0", "method": "session/update",
  "params": { "sessionId": "…",
    "update": {
      "sessionUpdate": "available_commands_update",
      "availableCommands": [
        { "name": "compact",
          "description": "Clear conversation history but keep a summary in context",
          "input": { "hint": "<optional custom summarization instructions>" } },
        { "name": "security-review", "description": "…", "input": null }
      ] } } }
Fields
name (without the slash), description (may be empty), optional input: only { hint } exists ("unstructured": everything typed after the name is the input). _meta may appear anywhere; ignore it.
When
  • Right after session/new, session/load and session/resume, from a setTimeout: it arrives just after the response, never inside it.
  • Again during the session, whenever the list changes: Claude's commands_changed (skills found as the agent works in a subdirectory), and after its first system/init frame filters terminal-bound commands.
Rule
Each update replaces the whole list for that session (the adapter's own comment: "The client should REPLACE its cached command list"). Never merge.
Today
ACPProtocol.event(fromUpdate:sessionId:) returns .ignored("available_commands_update") through its default: branch, and M1 pinned that with a test (ACPProtocolTests, "available_commands_update" → .ignored). That test changes with this work.

ACP-03

Running a command

Technical

There is no command request in ACP. A command runs when the prompt's first content block is text that starts with /name:

{ "method": "session/prompt",
  "params": { "sessionId": "…",
    "prompt": [ { "type": "text", "text": "/review 212" } ] } }
Rules
  • Send the message text exactly as typed: no trimming of the leading slash, no prefix, no rewriting of mcp:.
  • Files attached after the command (Rocky's PromptAttachment blocks) follow the text block as today. A file badge placed before the slash makes it an ordinary message (KIT-02).
  • The rest is an ordinary turn: the same session/update stream, the same stop reasons, Stop cancels it (session/cancel).
  • A local-only Claude command may end the turn without echoing the user message; Rocky already shows the user message itself, so nothing changes.
Today
ACPProtocol.promptParams(sessionId:text:) builds this already; commands need no new request, only this guarantee (test in KIT).
ACP-04

History and replay

Technical

Rocky stores the user message as sent ("/compact"). On session/load, Claude's adapter strips its local-command markers (<command-name>…) from the replay, so Rocky never sees them; no filtering is needed on Rocky's side. The command list is not persisted: it comes again after every session/load.

RockyKit: model and pure logic

KIT-01

SlashCommand and where the list lives

Technical
public struct SlashCommand: Equatable, Sendable, Identifiable {
  public var id: String { name }
  public let name: String          // as announced, e.g. "compact", "mcp:linear:triage"
  public let description: String
  public let inputHint: String?    // input.hint
  public var isMCP: Bool { name.hasPrefix("mcp:") }
}
// SessionEvent gains:  case availableCommands([SlashCommand])
// ChatSessionModel:     public private(set) var commands: [SlashCommand]  // replaced on every event
//                       public private(set) var commandsReceived: Bool     // false until the first update
Per session
Each conversation's ChatSessionModel has its own list (the tab's agent and session). Switching tabs switches lists.
Cache
AppModel.lastCommands[repoId + agent] keeps the last list seen, in memory. A new conversation shows it while its own agent starts, marked as not yet confirmed (CMD-05), and replaces it when its first update arrives.
Parse
Entries without a string name are dropped; a missing description becomes ""; input null, missing or without hint → nil. Order kept as received.
KIT-02

When the popup opens: the trigger

Technical
public enum SlashQuery {
  /// nil when the popup must stay closed.
  public static func parse(text: String, caret: Int, firstIsAttachment: Bool) -> String?
}
Opens when
all of: the text's first character is "/"; no file badge comes before it (firstIsAttachment == false; badges are U+FFFC, PromptAttachment.marker); the caret is inside the first token (between the "/" and the first whitespace); the popup was not dismissed for this token. The query is the text between "/" and the caret.
Closes when
a space or newline follows the token (arguments start); the caret leaves the token; the first character stops being "/"; Esc (it stays closed until the token changes); a command is chosen; the message is sent.
Not a trigger
"/" anywhere else: src/openapi.ts, "a / b", a path pasted mid-sentence.
Tests
"/" → ""; "/rev" caret 4 → "rev"; "/review 12" caret 10 → nil; "src/foo" → nil; " /rev" → nil; badge + "/rev" → nil; "/rev" caret 1 → "".
KIT-03

Filtering and order

Technical
public enum SlashCommandFilter {
  public static func rank(_ commands: [SlashCommand], query: String) -> [SlashCommand]
}
Order
Case-insensitive. Empty query: the announced order. Otherwise, in tiers, each tier in announced order: (1) name starts with the query; (2) a segment of the name starts with it (segments split on :, -, _: "rev" finds security-review, "tri" finds mcp:linear:triage); (3) the name contains it; (4) the description contains it. Nothing else matches.
Highlight
The matched part of the name is drawn in accent (tiers 1–3).
Tests
Each tier; ties keep announced order; a query matching only descriptions; a 300-command list ranks in under 5 ms.

The popup and the message box

CMD-01

Popup layout

In scope
Place
Above the message box, 8 pt over its top edge, as wide as the box; it grows upward. Background panel, radius 10, hairline ring and shadow like Rocky's menus. Appears in 120 ms (opacity and 4 pt rise).
List
Rows of 32 pt in a 4 pt inset, at most 8 visible (264 pt) and then it scrolls, keeping the selected row in view. The first row is selected when the list changes.
Footer
28 pt, hairline on top, 11 pt textTertiary: "↑↓ navigate · Return run · Tab complete · Esc close", and on the right the agent and count ("Claude Code · 42").
SwiftUI
An overlay on the composer in ChatView, not a window: the text view keeps focus while the popup is open.

CMD-03

Keyboard and mouse

In scope
Keys
While the popup is open, the message box's text view forwards: ↑ / ↓ (move, wraps), Return (CMD-04), Tab (complete), Esc (close). Every other key edits the text, which re-runs KIT-02 and KIT-03. ⇧Tab keeps switching plan mode.
Esc first
Since M2.5, Esc during a turn cancels it in ChatView's key monitor, which runs before the text view. That monitor skips when the popup is open (like it does for menus, the settings modal and sheets), so Esc closes the popup and the turn keeps running.
Mouse
Hover selects; click runs Return on that row.
SwiftUI
ComposerTextView.keyDown (Composer.swift) today handles Return and ⇧Tab; it checks the popup's state first and hands those four keys to a SlashCommandPopupModel owned by ComposerController. IME composition (hasMarkedText()) never triggers it.
CMD-04

Choosing a command

In scope
Return
Command without inputHint: replace the token with "/name" and send at once. Command with a hint: replace the token with "/name " (trailing space), close the popup, and show the hint as ghost text after the caret until the first character is typed.
Tab
Always completes: "/name " and the ghost hint, never sends.
No match
Return sends the text as an ordinary message; the agent decides what "/foo" means.
While running
The popup works the same during a turn. Sending goes into M2.5's message queue: "/name" becomes a queued row at the end of the transcript, after "Working", and goes out when the turn ends. It is still one session/prompt whose text starts with "/name" (ACP-03).

CMD-06

A sent command in the conversation

In scope

The user message starts with a chip: "/name" 12.5 mono in accent text on accent at 14 %, radius 6, 22 pt high, then the arguments as normal text. Only when the name is in the conversation's command list at the time it is drawn; otherwise the message shows as typed. UserMessageRow (ActivityRows.swift) draws it.

CMD-07

Finding the feature

In scope

The message box's "+" menu gains "Commands" with the hint "/": it inserts "/" at the start of an empty message (or selects the whole message's start when it has text and puts "/" there) and opens the popup. The placeholder stays as today.

Titles and accessibility

TITLE-01

Commands do not name a conversation

In scope

Today the conversation's title comes from its first message (ChatSessionRecord.title(from:), two call sites in AppModel). A message that is a command ("/compact", "/init") must not become the title: the title comes from the first message that is not a command. This also keeps the sidebar row titles meaningful (M2.5 ROW-02). Try it: the "New conversation" tab, send "/init", then a normal message.

Kit
ChatSessionRecord.title(from:) returns nil for text that starts with "/" and whose first token is a known command; callers keep looking. Test both cases.
