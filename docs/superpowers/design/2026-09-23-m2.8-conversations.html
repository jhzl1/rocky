Rocky · Conversations (M2.8)

+ opens a conversation at once, with the agent you last used in that repository. The agent is chosen afterwards in the message box's model menu: pick a model of another agent, and an empty conversation switches to it; one with messages stays as it is and a new conversation opens with that agent. Try it: + in "lima", then the model menu.

Demo controls, not part of Rocky

The rest (AGM-01…07, KIT-12, the rest of KIT-11), KBD-04 and the mini-modals (DLG-01…06, user request 2026-09-25) are this milestone. AGM-02

Switching an empty conversation

Technical
When
The picked model belongs to another agent, and the conversation has no user message and none queued.
Does
  1. Stop its agent (ChatSessionModel.stop()), also while it is still starting.
  2. Update the record: agent = the new one, acpSessionId = nil (otherwise a resume would load a Claude session id in OpenCode).
  3. Build a new ChatSessionModel for the same record id and start it; the tab keeps its place and its selection, its icon changes.
  4. When the new session reports its options, set the picked model. If the model is gone from the agent's list, keep the agent's default and show "GPT-5.5 isn't available in OpenCode; using Claude Sonnet 5".
Keeps
The unsent draft (text and attachments) and the message box focus.
Menu
Stays open (AGM-07): the rail's current dot moves to the new agent, the body keeps its models with the picked one checked and a spinner after the agent's name (AGM-05), and the Effort row appears with its animation once the session reports it. Key the menu by conversation id, not by the ChatSessionModel's identity (today "model-\(ObjectIdentifier(chat))"), so rebuilding the chat does not close it.
Also
The new agent brings its own slash commands (M2.6): its handler is installed before its session/new, like any new chat.

In scope

AGM-04

The model catalog

Technical
Why
An agent reports its models only in a session (the model config option, after session/new). So the menu lists from a catalog, and starts an agent only when the catalog has nothing for it (No list yet).
Rule
Every time a session reports its model option, Rocky records its choices (value, name, detail) for that agent. Claude's are keyed by Claude instance (claudeConfigDir, or "default"), because instances can differ; OpenCode's by agent only. The menu shows the list for the repository's Claude instance.
Stored
JSON at ~/Library/Application Support/Rocky/agent-models.json, rewritten when a list changes. Model names only: no tokens, no keys, and no effort levels (an agent reports them only for its current model, AGM-07).
No list yet
Rocky loads it by itself (user decision, 2026-09-25: "la idea es que cargue solo, sin yo tener que darle a un botón"; the "Start OpenCode" button is gone). When the rail shows an agent the catalog has no list for (it never ran on this Mac, or not with this Claude instance), AppModel.loadModelsIfNeeded starts that agent once, in the background and in no conversation: no history, nothing stored. It runs until its session reports its model option; the catalog records the choices, and the process stops. One run at a time per agent and Claude instance: showing the agent again while it loads waits on the same run. Meanwhile the body shows the centred spinner (AGM-05).
Failure
The body shows "Couldn't load OpenCode's models: reason" (12.5 textSecondary, centred, wrapping), and showing the agent again retries. An agent whose session neither reports its models nor fails within 30 s (AppModel.modelProbeTimeout) is stopped and counts as failed, with the reason "it didn't answer in 30 s", so the spinner never stays for good. The timer covers the session start only, not the agent's install on first use, which can take longer.
Cost
The one exception to "an agent starts on its first message" (spec Section 1): once per agent and Claude instance on this Mac, since the list is kept (Stored), plus a retry after a failure. With a list, showing an agent never starts it.

AGM-07

Effort follows the model

Technical
Source
The session's effort config option (category thought_level), never a fixed list. OpenCode 1.18.32 builds it from the current model's variants plus "default", and omits it for a model without variants (packages/opencode/src/acp/config-option.ts, buildEffortSelectOption). So GPT-5.5 might offer Minimal · Low · Medium · High · Default, Claude Sonnet High · Max · Default, and Qwen3 Coder nothing. Claude's adapter also changes its levels with the model.
Model change
The agent answers session/set_config_option with the whole new list, and Rocky replaces its options with it (ChatSessionModel.setOption, as today). OpenCode resets the effort to the new model's "default" (else its first level) unless the model is the same (service.ts, selectModelVariant). Rocky shows what comes back and never carries "High" over by itself.
Menu
The Effort row shows exactly those choices, in the agent's order, as equal-width chips (1 to 6 fit in 380 pt), and disappears when the option is absent.
Stays open
Picking a model never closes the menu, with or without effort levels, so changing the effort right after is one click (user decision, 2026-09-23; today the pick closes it). Picking an effort keeps it open too, as today. It closes on Esc, a click outside, sending, or when another tab takes over (AGM-03).
Motion
  • Appears (the new model has levels, the last had none, or the session just reported them): the Effort section, divider and title included, grows from 0 to its height while fading in and rising 4 pt, 200 ms ease-out (Theme.Motion.enter). The menu grows upwards, since it hangs from its button.
  • Goes (the new model has none): it shrinks to 0 and fades, 120 ms ease-in.
  • Other levels (both models have levels): the chip labels cross-fade in 150 ms and the selected fill slides to the new model's level.
  • Effort picked: the selected fill slides from the old chip to the new one, 180 ms ease-out.
  • Reduce Motion: fades only, no growth, no slide.
SwiftUI
The section in an if with .transition(.opacity.combined(with: .move(edge: .bottom))), its insertion under withAnimation(Theme.Motion.enter) when the options change; the fill as one background with matchedGeometryEffect in EffortChips; @Environment(\.accessibilityReduceMotion) for the fade-only path. The menu host must let its height follow the content (check MenuPresenter does not fix it).
Label
The button and the selected row show the effort after the model ("GPT-5.5 High"), except "Default", which is left out ("GPT-5.5", not "GPT-5.5 Default"). The chip keeps its "Default" name.
Other agent
Its body shows no effort, because the agent reports levels only for its current model. After the switch (AGM-02) or the new conversation (AGM-03), the model starts at its default effort, and the Effort row is in the menu from then on.
Done when
With OpenCode: picking GPT-5.5 keeps the menu open and animates its levels in; picking Qwen3 Coder animates the row out and the menu stays; picking Claude Sonnet after GPT-5.5 High shows Sonnet's default, not High.

Keyboard

KBD-04

⌃` toggles the terminal

In scope
Why
User, 2026-09-25 (relayed by dev-1): "quiero agregarle el atajo de teclado ctrl + ` para abrir la consola, así como hace vsc". It completes VS Code's pair: ⌘J is Toggle Panel, which Rocky has (M2.5 TERM-05), and ⌃` is Toggle Terminal.
Does
  • A terminal has the keyboard: fold the panel (TERM-05) and give the keyboard back to the selected tab: a conversation's message box, or the file or diff tab.
  • Otherwise: unfold the panel, select a terminal and give it the keyboard. Which terminal: the selected tab if it is one; else the first terminal tab; with none, a new "Terminal N", as New Terminal does (TERM-07; the first may wait for the repository account's token, ENV-01), focused once it is there.
  • The Setup and Run tabs are scripts, not terminals: ⌃` never selects them, and with only those it makes a terminal.
  • The fold is TERM-05's, global and remembered (terminalPanelCollapsed), so ⌘J and ⌃` agree.
Menu
View ▸ "Toggle Terminal" ⌃`, disabled with no workspace selected: a menu command with .keyboardShortcut("`", modifiers: .control), in the CommandGroup(after: .sidebar) section that holds SidebarCommand and PullRequestPanelCommand.
Collisions
None, checked 2026-09-25. macOS's default shortcuts use ⌘` (Move focus to next window), not ⌃`. No Rocky command, view shortcut or spec uses it (⌘J is a view shortcut in WorkspacePanelView). SwiftTerm 1.20.0's MacTerminalView overrides keyDown but not performKeyEquivalent, so the menu gets ⌃` before the shell, as it gets ⌘J. The cost: a shell no longer receives ⌃` (NUL), which ⌃Space still sends. The user's layout, us-altgr-intl, types ` directly; on a layout where ` is a dead key the shortcut may not fire, as in VS Code.
Motion
TERM-05's: the panel's height, 150 ms ease-out; instant with Reduce Motion.
Done when
From the message box, ⌃` unfolds the panel on a terminal with the caret in it, and typing goes to the shell; ⌃` again folds the panel and the caret is back in the message box. In a workspace with no terminal, ⌃` makes "Terminal 1" and focuses it.

DLG-03

Keys and focus

In scope
Keys
Return triggers the default button; Esc triggers Cancel (the error modal's OK). Tab and ⇧Tab move the keyboard focus between the buttons, drawn as KBD-01's 2 pt accent ring; Space presses the focused one, and so does Return once the focus has moved. ⌘D presses "Don't Save" where there is one, as in the native prompt. In the Commit modal, Return in a text field types a line; ⌘Return commits.
Order
Esc goes first to an open Rocky menu, then the mini-modal, then Settings, then the agent's turn (CLAUDE.md, key monitors). While a mini-modal shows, the keys behind it do nothing: the message box, the terminal and the shortcuts wait.
SwiftUI
One local NSEvent monitor, installed while the host shows a dialog and removed after, reading the live dialog through a reference (LiveFlag's pattern), since a monitor keeps the view as it was when added.
DLG-04

Placement, motion, one at a time

In scope
Where
Centred on the window, the same for every mini-modal: each one blocks until answered, as the native window-modal sheets did, and one rule is easier to learn than "the pane it concerns". The permission request still shows only while its conversation is on screen, as today's sheet does.
Motion
The dim fades in 150 ms (Theme.Motion.state); the panel fades and grows from 0.98, as the Settings panel does. Closing: 120 ms, faster than opening. Reduce Motion: fades only.
One at a time
A second request waits in the queue and shows when the first closes, in order. ⌘Q is the one exception: it cancels the current mini-modal, as Esc would, and shows the quit prompt (DLG-05).
DLG-05

The quit prompt

Technical
Flow
applicationShouldTerminate returns .terminateLater when there are unsaved edits, shows the mini-modal, and the answer calls NSApp.reply(toApplicationShouldTerminate:): Save All saves, then quits, or cancels and shows the file that failed (today's rule); Don't Save quits; Cancel replies false.
Hidden
Minimized, hidden or on another Space: Rocky unhides, deminiaturizes and activates its window first (NSApp.unhide, deminiaturize, makeKeyAndOrderFront), then shows the modal on it.
No window
After ⌘W closed the window, Rocky keeps today's NSAlert, the one native dialog left: an in-app modal needs a window, and reopening the whole window only to ask would be worse.
