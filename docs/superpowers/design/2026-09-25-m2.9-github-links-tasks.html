GHL-03

What the picker fetches

Technical
Account
The repository's GitHub account (M2.7 ACC-01), over URLSession GraphQL (GitHubClient), never a gh process.
Lists
When a tab first shows in an opening of the picker: Issues, repository.issues(states: OPEN, first: 30, orderBy: {field: UPDATED_AT, direction: DESC}) with number, title, state; Pull requests, pullRequests(states: OPEN, …) with number, title, isDraft, headRefName, baseRefName, isCrossRepository.
Search
Typing, debounced 250 ms: search(type: ISSUE, first: 30, query: "repo:owner/name is:issue is:open text") (is:pr for pull requests). Text that is a number, "212" or "#212", also asks issue(number:) / pullRequest(number:) directly, in any state, and shows it first. A newer keystroke and closing the picker cancel the request in flight. GitHub's search allows 30 requests a minute; the debounce keeps ordinary typing under it, and a rate-limit answer shows as the error.
Branches
From git, no GitHub call: git for-each-ref refs/heads refs/remotes/origin --sort=-committerdate (name, upstream), filtered in memory; a remote branch with a local one of the same name shows once, as local; origin/HEAD is left out. When the tab first shows, one git fetch origin --prune runs in the background and the list refreshes when it ends. git worktree list --porcelain tells which branches another worktree holds.
At rest
Nothing: no polling and no cache after the picker closes (spec Section 1).

GHL-05

Linking a pull request or a branch

In scope
Does
Switches the worktree to that branch, then attaches a file like GHL-04's: a pull request, [GITHUB]-PR-131.md (GHL-04's format plus "- Branch: fix/webhook-retry → development" and "- Draft: yes" when it is one); a branch, [BRANCH]-feat-button-styles.md ("/" becomes "-"), with its name, upstream, and git log --oneline of its commits the base lacks (the last 20). The chip shows the git-pull-request or git-branch mark.
Only when
The workspace has nothing of its own: no uncommitted changes, no commits its base lacks (LocalGitStatus.uncommitted and commitsAheadOfBase both 0, HDR-02's "No changes yet"), and no file tab with unsaved edits (EDIT-02). Otherwise the Pull requests and Branches tabs start with a notice, "This workspace has changes of its own. Switching needs one with none: create a workspace for it.", in an attention 8 % box, and their rows are disabled. Checked again at pick time.
How
A local branch: git switch branch. A remote-only branch: git switch --track origin/branch. A pull request: git fetch origin headRefName, then the same as its branch. Rows Rocky cannot switch to are disabled with the reason: a branch another worktree holds (git refuses it: "Checked out in path"), the current branch, a pull request from a fork (isCrossRepository, OUT-50).
After
  • The workspace's own branch (rocky/lima), empty as just checked, is deleted locally, so switched workspaces leave no empty branches behind (user decision, 2026-09-25: "Borrarla").
  • A pull request sets the workspace's baseRef to origin/baseRefName, so Changes (M3 GIT-01) and the header compare against the pull request's base. A branch keeps the workspace's base.
  • The top bar's branch shows the new name; All files and Changes refresh through FSEvents; the pull request panel looks the branch up at once (M2.7 PR-01) instead of waiting for its next poll.
  • Running scripts, tasks and terminals keep running, now on the new branch's files. Removing the chip does not switch back.
  • A git failure shows a toast with git's message; nothing is attached and the workspace stays as it was.
Not done
Rocky does not rename the branch, write "closes #N" or edit the pull request (user decision; the agent does it from its own instructions).
Done when
In a new workspace, picking #131 switches it to fix/webhook-retry, the right panel shows that pull request, and rocky/city is gone from git branch. In a workspace with changes, the rows are disabled under the notice.

B · VS Code tasks

TSK-01

Reading tasks.json

Technical
Where
worktree/.vscode/tasks.json; when the worktree has none, the main clone's, since .vscode is often ignored and WorktreeLinker links only what links names. ${workspaceFolder} is always the worktree.
When
Each time the Run menu opens or its main part is clicked. No file watching, no polling; the file is small.
Format
JSON with comments and trailing commas, as VS Code reads it: JSONDecoder with allowsJSON5 = true (native, macOS 12+) accepts both. version must be "2.0.0". acme-platform's file (checked 2026-09-25): 27 tasks, 19 of them "_", // comments, no trailing commas.
Read
label, type, command, args, options.cwd, options.env, dependsOn, dependsOrder, isBackground, problemMatcher[].background.beginsPattern / endsPattern (a string, or an object with regexp), presentation.reveal / focus / panel / clear / echo, detail, hide, group (only isDefault), osx (merged over the task), and inputs (id, type, description, options, default, password). Anything else is ignored.
Listed
In file order, every task whose label does not start with "_" and without "hide": true (VS Code's own way to hide one). Hidden tasks still run as dependencies.

TSK-03

Running a task

In scope
Process
type: "shell": command and its args joined by spaces, each arg (a string, or an object's value) in single quotes when it holds spaces or shell characters (VS Code's "strong" quoting), run as scripts run today: /bin/zsh -c in a PTYSession (PTYSession.swift:21). type: "process": the command runs directly with its args, no shell. Environment: the workspace's (ENV-01, with PORT and ROCKY_*), then options.env on top. Directory: options.cwd, else the worktree.
Tab
Each task, dependencies included, runs in a panel tab titled with its label, with the script tabs' status dot and end line (TERM-03). presentation.panel: "dedicated", the task's own tab, reused on its next run; "new", a new tab each run; "shared" (VS Code's default), one tab the shared tasks reuse once its last task ended (else a new one), titled with the task it runs. Closing a task's tab stops that process.
Presentation
reveal "always" (the default) selects the tab and unfolds the panel; "silent" and "never" do neither, and the dot still shows. focus: true gives the terminal the keyboard. clear: true clears a reused tab first. echo (default true) writes "> resolved command" first, in textTertiary, like VS Code's "Executing task".
Run mode
When the repository's run scripts do not run concurrently (runScriptMode), starting a task first stops the Run script and tasks of every other workspace, in every repository, as the Run script does today (AppModel.startRun loops over all workspaces' processes): tasks bind fixed ports too (8000 and 6379 in acme-platform).
Done when
"Run: Web" asks the web mode, runs "_Dev: Stop stray processes" in a shared tab without selecting it, then opens a "Run: Web" tab running pnpm dev-local in apps/web.
TSK-04

Variables and inputs

In scope
Variables
In command, args, options.cwd and options.env: ${workspaceFolder} (and its old name ${workspaceRoot}), ${workspaceFolderBasename}, ${userHome}, ${cwd} (the worktree), ${pathSeparator}, ${env:NAME} (from the task's environment), ${input:id}. Any other is an error before anything starts (TSK-07).
pickString
Rocky's menu above the Run button, with the input's description as its caption and one item per option (its label, or the string); the default is checked and highlighted, so Return takes it. Esc cancels the whole run. MenuPresenter gains what this needs: ↑/↓ and Return, a highlighted item on open, and an onCancel for Esc and a click outside.
promptString
A mini-modal (M2.8 DLG-02) holding a field: the description as its title, the field 28 pt with the default selected, password: true making it a secure field; Cancel · Run (primary, default). Return confirms, Esc cancels the run.
Once
Every ${input:…} of the task and its whole dependency chain is asked before anything starts, in order of first use, and one id gets one answer for the whole chain: acme-platform's "Run: API + Web" and its dependency "_API: Run (mode)" both read stackMode, and must agree. Answers are not remembered between runs, as in VS Code; the default is preselected.
TSK-05

Dependencies

Technical
Order
dependsOn (a label or a list) runs first, recursively. dependsOrder "sequence": one after another, in the list's order; "parallel" (the default): all at once. The task starts when all are done. A task reached twice in one chain runs once.
Done
A normal task: it exits with code 0. A background task (isBackground: true): a line of its output, ANSI escapes removed, matches its endsPattern (a regular expression); its process keeps running. A background task without an endsPattern counts as done as soon as it starts: Rocky does not guess a wait (VS Code needs the pattern for this too).
Already running
A dependency already running in this workspace is not started again: a background one that matched its pattern counts as done, one still starting is waited for, a normal one still running is waited for.
Failure
A dependency that exits non-zero, or a background one that exits before its pattern, stops the chain: what has not started does not start, its tab shows the danger dot, and a toast says "“_Dev: Stop stray processes” failed, so “Run: Web” didn't start", with Show (selects that tab). Dependencies already running keep running.
TSK-06

Stopping

In scope
Stop
The main part's "■ Stop" stops the default task and the dependencies this run started that no other running task needs, newest first, with the Run script's stop (today's stopRun path) and its end line "Process stopped".
Tab
Closing a task's tab stops only that process.
Always
Removing the workspace and quitting Rocky stop its tasks, as they stop its scripts and terminals today.
TSK-07

Errors

In scope
CaseWhat Rocky shows
tasks.json does not parse, or its version is not 2.0.0The menu's tasks part is one disabled item, "tasks.json can't be read", with the decoder's message as its second line ("Line 41: …"). The Run script still runs; a task default falls back (TSK-02).
A type other than shell or processThat item is disabled; tooltip "Type “npm” isn't supported: Rocky runs shell and process tasks".
An unknown variable, an input of type: "command", or an ${input:id} with no such inputNothing starts; toast "“Run: X” uses ${file}, which Rocky doesn't support".
A dependsOn label the file lacksNothing starts; toast "“Run: X” depends on “_Y”, which tasks.json doesn't have".
A dependency cycleNothing starts; toast "“A” and “B” depend on each other".
An endsPattern that is not a valid regular expressionNothing starts; toast "“_API: Run (mode)” has an invalid endsPattern".

WSC-01

Instant, and one at a time

In scope
Why
User, 2026-09-28 (relayed by dev-1): "la idea es que se abra de una vez el worktree y que todo vaya cargando poco a poco" and "si le doy varias veces al botón de crear un worktree, me deja. Clicking "+" again started 15 creations at once.
Does
A click on a repository's "+" (or ⌘N, or New Workspace in its menu) picks the name (WorkspaceNamer), adds the row at once, selected, and opens the workspace's view before git has done anything. Git's part (WSC-04) follows in the background, and Setup after it (WSC-05).

Tooltip: "Wait for lima to be created" while git runs, "Wait for lima to finish setting up" during Setup. They turn off in the same run of the main actor as the click, before any await, so a double click cannot start two.
Released
When that workspace's Setup ends: it succeeds, it fails, the user stops it (closing or stopping the Setup tab), the workspace is removed, or its creation fails (WSC-06). A repository with no hook and no Setup script releases it as soon as the worktree exists. Retry takes it again.
Gone
The global busyMessage "Creating workspace…" at the bottom of the window.
Done when
In acme-platform, "+" shows the new row and its view within a frame; clicking "+" five times makes one workspace; ledger's "+" stays disabled until acme-platform's pnpm install and Setup end.

WSC-04

Git's part, without hooks

Technical
Steps
(1) The base, as today (WorktreeService.baseRef: fetch, then the base branch). (2) git -c core.hooksPath=/dev/null worktree add -b rocky/lima path base: no hook runs, so it returns after the checkout, in seconds. (3) The workspace is saved, its environment files are linked (WorktreeLinker, before any script, as today), and the conversation's agent starts, since its conversation is on screen (spec Section 1). (4) Setup (WSC-05).
Fetch
A failed fetch does not stop it, as today, but says so in a toast instead of an alert: "git fetch failed; lima was created from the last fetched origin/development."
Agent
It starts before Setup ends: the user can talk to it while pnpm install runs ("que todo vaya cargando poco a poco"). A command the agent runs before the dependencies are in may fail; the agent sees that and the Setup tab shows why.
WSC-05

Setup: the hook, then the Setup script

In scope
Hook
The repository's own post-checkout hook runs first, visibly, where git would have run it: the path git rev-parse --git-path hooks/post-checkout gives in the worktree (it honors core.hooksPath: .husky/post-checkout in acme-platform), only when that file exists and is executable, as git requires. Arguments as git passes them for a new worktree: 0000000000000000000000000000000000000000 HEAD 1. Directory: the worktree; environment: the workspace's (ENV-01). No hook: the step is skipped.
Then
The Setup script (rocky.json or the repository settings), as today. Without either, there is no Setup tab.
Tab
One Setup tab, selected and unfolded when it starts, holding both steps in order. Each step opens with a line in textTertiary: "▸ post-checkout hook · .husky/post-checkout", "▸ Setup · pnpm db:migrate", and ends with its end line (TERM-03): "post-checkout exited with code 0". The tab's dot runs until the last step ends.
Failure
A step that exits non-zero stops the next one: the dot turns danger, the row shows ROW-03's Setup failure, and the workspace stays usable. The hook's exit decides this, as it decides git checkout's own exit status.
Risk
acme-platform's link-worktree.sh also creates symlinks that WorktreeLinker has made just before; the hook calls it as … || true, and the linker leaves existing files alone, so neither order breaks. A hook that expects git's environment variables beyond the three arguments is not covered: not known to exist here.
Done when
A new acme-platform workspace opens at once; a moment later its Setup tab shows pnpm install's progress under "▸ post-checkout hook", while the agent already answers.

WSC-07

Removing a workspace

In scope
Why
User, 2026-09-28 (relayed by dev-1): "cuando remuevo un worktree se ve esto durante unos segundos y luego aparece algo de git branch fatal no sé qué y luego sí se borra, ¿por qué?". Today AppModel.removeWorkspace keeps the workspace selected while git worktree remove deletes its files (node_modules included, for seconds): its FileWatcher and pull request refreshes keep going, Changes lists every file as deleted (+0 −19.1k), a git read inside the half-deleted folder fails with "fatal:", and the view says "Opening the conversation…" because its chats were stopped first.
Order

A rocky/city branch is deleted locally when git rev-list --count refs/heads/branch --not --exclude=branch --branches --remotes --tags is 0, the check WorktreeService.cleanUp already uses; otherwise it is kept, so no commit is lost.
