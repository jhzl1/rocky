Rocky · All changes (M3.1)

All changes in the Changes tab opens one center tab with every changed file's diff, Uncommitted then Committed, each file under a sticky header that folds. It reads only: a file's name opens its own diff tab for comments, edits and discards. Try it: fold a file, "Collapse all", "Next file (⌥⌘↓)", then scroll down and "The agent adds a file above" to see the scroll stay put.

The tab

ALL-01

Opening it

In scope
Button
In the Changes tab's 30 pt row (CHG-02), right before "⋯": All changes, a text button (RockyTextButtonStyle, 24 pt, 12 textSecondary) with rectangle.stack 12. In the row, not in "⋯", so the way to read everything at once is seen, not hunted for. Tooltip "Every changed file in one tab". With no changes it is disabled, tooltip "No changes yet".
Does
Opens the workspace's All changes tab at the end of the tab row and selects it; if it is already open, selects it. One per workspace. It is a permanent tab, never a preview (M3's preview tabs are for files).
Done when
With 5 changed files, one click shows them all in the center, and a second click only selects that tab.
ALL-02

The tab itself

In scope
Title
rectangle.stack 12 in textSecondary, "All changes", then the number of changed files (11 mono textTertiary, as the Changes tab's count, CHG-01; hidden at 0). A tab of TAB-01's kind: the underline when selected, × on hover or when selected. Tooltip "All changed files: Uncommitted, then Committed".
Lives
As a diff tab does (DIFF-01): it stays open until closed, and switching tabs or workspaces keeps its scroll position and fold state (ALL-05).

What it shows

ALL-03

Layout and file headers

In scope
Toolbar
34 pt with a hairline under it, in line with the Changes tab's row: "5 files" (12 textSecondary), the total DiffStatLabel, a spacer, then Collapse all (text button, arrow.down.right.and.arrow.up.left 11), which reads Expand all once every file is folded.
Order
WorkspaceChanges.listOrder: the "Uncommitted · 2" and "Committed · 3" captions (CHG-03's: 10.5 uppercase textTertiary, 28 pt), each followed by its files, in the Changes tab's order. A section with no files is left out.
Header
Per file, 34 pt, background fill with a hairline above and below: a 18 pt fold chevron (chevron.down 9, textTertiary, turned −90° when folded, 150 ms), the status letter (CHG-03), the file's icon (FIL-09, 14), the directory (textTertiary) and the name (textPrimary) at 12.5, a note in 11 textTertiary ("New file", "Renamed from src/old/api.ts"), a spacer, and DiffStatLabel.
Clicks
The name opens that file's own diff tab (DIFF-01), as its Changes row does, or selects it if open; hover underlines it, tooltip "Open in its own tab". The chevron and the rest of the header fold and unfold the file.
Sticky
Yes: a file's header stays at the top of the tab while its rows scroll under it, and the next file's header pushes it up, so the file on screen is always named. SwiftUI: one Section per file in a LazyVStack(pinnedViews: .sectionHeaders).
Done when
Scrolling through a long file keeps its header at the top; clicking its name opens the file's diff tab; clicking beside the name folds it.
ALL-04

The rows

In scope
Rows
DIFF-02's, unchanged: 20 pt rows, 12 mono, one 48 pt number column, the + / − marker column, syntax colors (DIFF-04), no @@ rows, three context lines, and "⋯ N unchanged lines" (26 pt) between, before and after hunks, expanding on click. The existing DiffLineRow, DiffGapRow and DiffCaptionRow, whose fixed heights keep the lazy stack's scroll bar steady.
Sideways
Long lines do not wrap. The whole list scrolls sideways together, as one diff tab does: the number and marker columns and the file headers stay at the left edge (Sticky, DiffScrollOffset) while the code moves. Its width is the widest line among unfolded files.
Between
8 pt of space after each file's last row, before the next header.
Read only
No comment "+" on hover (CMT-01), no Discard, no Edit, no Diff | Edit control: those are in each file's own diff tab (OUT-11). Text stays selectable for copying.
ALL-05

Folding

In scope
Start
Every file unfolded, except those DIFF-03 already keeps short (ALL-07). Unfolding is instant: rows appear and disappear without a height animation (fixed heights, no jump); only the chevron turns.
All
Collapse all folds every file; Expand all unfolds every one, but a large file stays at its "Show" caption (ALL-07).
Kept
Per workspace, in memory, by path: which files are folded and which unchanged runs are expanded. They survive switching tabs and workspaces and closing and reopening the tab, and go when Rocky quits (like ROW-04's unread marks). A file that leaves the list and comes back returns unfolded; a file whose hunks move loses its expanded runs, as a diff tab does.
ALL-06

Keyboard

In scope
Files
With the All changes tab selected, ⌥⌘↓ / ⌥⌘↑ (KBD-02's next / previous file) scroll to the next / previous file's header, which becomes the current file: its header shows a 3 pt accent bar at its left edge. They do not open diff tabs there; elsewhere they keep walking the Changes list as today. The current file starts as the one whose header is at the top.
Others
Return opens the current file's own diff tab. No new chords: folding stays on the header. No find: a diff tab in Diff mode has none today (the system find bar is the Edit mode's editor's, CodeEditor), so there is nothing to match; find across the tab is OUT-11.

ALL-08

Empty

In scope

No changed files: the toolbar reads "No files", its button is disabled, and the list shows CHG-03's empty state centred: "No changes yet" (13 textSecondary) and "Changes the agent makes in this workspace show up here." (12 textTertiary). An open tab whose last change goes (a commit that is then merged, a discard) shows it too; it does not close itself.

ALL-09

Live updates and the scroll position

In scope
Diff
GIT-01 computes the full diff only while the Changes tab is visible; now also while the workspace's All changes tab is the selected tab (and the window can be seen). It follows the agent's edits live, with GIT-01's 500 ms debounce.
Anchor
What is on screen stays on screen. The anchor is the first row at the top of the list: its file's path and its line (new number, or old one for a removed line). When an update adds, removes or resizes files or hunks above it, the scroll position moves by the same amount, so the anchor row keeps its place. If the anchor's line is gone, the nearest row of the same file; if the file is gone, the next file's header. Updates below the anchor move nothing. SwiftUI: .scrollPosition(id:anchor: .top) on the rows' stable ids (KIT-21).
No motion
Files that arrive or change do not animate and there is no "new" badge: the agent's edits keep coming, and a list that jumps or flashes on each one cannot be read.
Done when
Scrolled into the third file, a new file added above it by the agent appears when you scroll up, while the line you were reading does not move.

The short message

In scope
Text
With several comments: "Address the 4 review comments on pull request #131 in the attached file, and say what you changed for each number." With one: "Address the review comment on pull request #131 in the attached file, and say what you changed." The number comes from the comments sent, not from the whole list.
Same way

RockyKit

KIT-21

AllChangesLayout

Technical
struct AllChangesState { var folded: Set<String>; var expandedGaps: [String: Set<DiffGap>]; var shownLarge: Set<String> }
struct AllChangesSection {               // one pinned Section per file (ALL-03)
  let path: String
  let kindCaption: (kind, count)?        // "Uncommitted · 2" / "Committed · 3", on a kind's first file
  let header: AllChangesHeader           // the FileDiff and whether it is folded
  let rows: [AllChangesRow]              // line, gap, caption, spacer; ids stable across updates, from path + line
}
enum AllChangesLayout {
  static func sections(changes: WorkspaceChanges, state: AllChangesState, newLines: [String: [String]]) -> [AllChangesSection]
  static func anchor(after update: [AllChangesSection], was: AllChangesRow.ID, previousPaths: [String]) -> AllChangesRow.ID
}

Sections instead of one flat list of rows (dev-1's plan, 2026-09-29): a pinned Section needs its header apart from its rows. anchor takes the previous order of paths to locate "the next file's header" when the anchor's file is gone.

Pure, on top of DiffLayout. Tests: Uncommitted then Committed with their counts; an empty section left out; a folded file gives only its header; a large file gives its caption until shown; binary, mode-only and pure-rename captions; ids stay the same when a file is added above; anchor falls back to the same file's nearest line, then to the next file's header in the previous order. AppModel: the workspace's AllChangesState in memory, and GIT-01's "Changes tab visible" condition widened.
