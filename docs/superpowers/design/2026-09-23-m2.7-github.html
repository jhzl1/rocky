Source
Local: git status --porcelain=v2 --branch (uncommitted, ahead/behind the upstream) on PR-07's triggers. Remote: behind/ahead of the base from GraphQL compare (PR-01); the pull request fields for the rest. No git fetch on a timer.
Upstream
When the PR's headRefOid (PR-01) differs from refs/remotes/origin/<branch>, Rocky runs git fetch origin <branch> once, so ahead/behind the upstream are current. Without a PR, the last fetch's numbers stand.
Incompatible
Ahead of and behind the upstream at once. Labelled "Remote branch was rebased" when that fetch was a forced update (the tracking ref's last reflog entry, git reflog -1 --format=%gs refs/remotes/origin/<branch>, contains "forced-update"); else "Incompatible with remote". So pull means behind only, and push means ahead only.
GST-02

Pull from the base

Technical

Conductor's order, run by Rocky with the workspace environment:

  1. Uncommitted changes: send the agent "Commit your changes, then bring in origin/development and push." (Rocky's wording; Conductor's is not known).
  2. Else git fetch origin development.
  3. Only behind (no commits of its own): git merge --ff-only origin/development; toast "Pulled latest changes. You're up to date!".
  4. Diverged: send the agent, depending on git config pull.rebase: "Merge origin/development into this branch. Then push." or "Rebase this branch onto origin/development. Then push --force-with-lease."

Rocky itself never creates a merge commit here and never force-pushes.

GST-03

Pull and push against the branch's remote

Technical

Pull ("Behind by N"): git pull; disabled with uncommitted changes (tooltip "Commit or discard the changes first"). Push ("Ahead by N"): git push (-u origin HEAD without an upstream). Both with the workspace environment, so GH_TOKEN (ENV-01) signs HTTPS. Push rejected as non-fast-forward: "The remote has new commits. Pull first." Never --force from Rocky.

AGT-03

Fix errors

Technical
Fix the failing CI actions. I've attached the failure logs.
Logs
For each failed GitHub Actions check run: GET /repos/{owner}/{repo}/actions/jobs/{databaseId}/logs (it redirects to the log), the last 1000 lines, saved to ~/Library/Application Support/Rocky/ci-logs/<workspace id>/<check name>.log (outside the worktree; the workspace's old logs are deleted first) and attached.

In scope

Account and token

ACC-01

GitHub account per repository

Technical
Accounts
Logins from gh auth status; a token per login from gh auth token --user <login>, once per launch on first need, in memory only, never stored or logged.
Binding
Repository setting "GitHub account" (the next free migration: repo.githubLogin); the default, in order: (1) the login equal to the remote's owner; (2) else the first logged-in account, the active one first, whose token can read the repository: one GraphQL repository(owner:, name:) { id } per login until one succeeds, once per repository per launch; (3) else gh's active account. Example: celes-app/celes-platform matches no login, jhzl1 gets a 404 and only ocampos-biai can read it, so step 2 picks ocampos-biai. Owner and name from git remote get-url origin (https, git@host:o/n.git, SSH aliases like github-celes).
Shown
Panel footer; the repository settings sheet has the picker. Its first entry is "Automatic (jhzl1)", naming the login the default resolves to; choosing it stores nil.
Errors
"GitHub access required" in the header (loading group) and gh auth login --hostname github.com in the tab.
ENV-01

GH_TOKEN for every workspace process

Technical

From M4 (spec Section 2, step 3, the token only). Agents, terminals and scripts of a workspace get GH_TOKEN = the repository account's token, the account layer of WorkspaceEnvironment, which comes last, as spec Section 3 says ("later wins": login env < repository variables < account variables). So the account's token wins over a repository variable named GH_TOKEN. (Corrected 2026-09-23: an earlier version put it before repository variables, against the spec.) Rocky sets no GIT_SSH_COMMAND for git (its fetch, pull and push included): a repository's own core.sshCommand, such as an includeIf that picks a per-account key, stays in effect (it failed when overridden, 2026-09-23). The agent's gh and HTTPS git act as that account (M0: gh auth git-credential honors GH_TOKEN; push itself was never exercised, so verify it). An account change applies to new processes (M2 rule); the settings sheet says "Restart the conversation's agent to use the new account". GIT_AUTHOR_*, SSH keys and the Claude instance per account stay in M4.

PR-05

Merge, with a choice of method

In scope
Methods
Only those the repository allows (squashMergeAllowed, mergeCommitAllowed, rebaseMergeAllowed). One allowed: a plain button. Two or three: a split button; its chevron opens the menu. (User decision, 2026-09-23: choose among the allowed methods. Conductor uses only the first.)
Default
viewerDefaultMergeMethod when allowed: GitHub's last method this viewer used on the repository, else the repository's default. Otherwise the first allowed in the order squash, rebase, merge. A pick from the menu stays the workspace's method until Rocky quits. GitHub records the merge itself, so the next default follows it, and Rocky stores nothing.
Button
24 pt, success fill (HDR-01), short label by method: "Squash", "Merge", "Rebase"; tooltip "Squash and merge into development".
Menu
Rocky's menu (MenuButton / MenuItem). One item per allowed method, with a second line (11.5 textTertiary) and a check at the item's right end on the current method; no leading column (HDR-04): Squash and merge "Combine all commits into one commit on development" · Rebase and merge "Replay each commit onto development, no merge commit" · Create a merge commit "Keep every commit and add a merge commit" (the order squash, rebase, merge). Rebase is disabled when canBeRebased is false: "GitHub can't rebase this branch cleanly".
Confirm
Two clicks: the first turns the button into "Confirm squash" / "Confirm merge" / "Confirm rebase" (attention) for 4 s (a Rocky choice; Conductor merges on one click). Picking another method cancels the confirmation.
Does
GraphQL mergePullRequest(input: {pullRequestId, mergeMethod: SQUASH | MERGE | REBASE}); "Merging…" with a spinner; errors under the header. The Git status row "Ready to merge" (GST-01) carries the same button, sharing its method and its confirmation.
Kit
Pure MergeMethods.available(repository:) -> [MergeMethod] and MergeMethods.initial(available:viewerDefault:) -> MergeMethod, each with tests (one allowed; the viewer's default not allowed; the order squash, rebase, merge).

PR-07

Technical
Rules
Selected workspace only, and only while the window is visible: it stops while the window cannot be seen (NSWindow.occlusionState without .visible: minimized, hidden, fully covered or on another Space), not when another app is active (user decision, 2026-09-24: "alive while visible"). Immediately on selection, when the window becomes visible again or active, after a Rocky action (merge, push, pull, ready, re-run), and when an agent turn in that workspace ends; then every 30 s, flat, and every 15 s while checks or deployments run. No backoff (user decision, 2026-09-24): a change made outside Rocky (an approval, a comment, a re-run on github.com) shows within 30 s. Cost: 120 GraphQL queries an hour for the selected workspace, well inside GitHub's 5,000-point hourly budget per account, each a URLSession request with no process. The local git status (GST-01) runs on the same triggers.
Stored
The last state per workspace (the next free migration: prNumber, prUrl, prState, prHeaderState, prChecks, prUpdatedAt, and hidden comment ids), shown for other workspaces and after relaunch.
Footer
The account and "Updated 12s ago" (it keeps counting while the window is visible); no manual refresh button, since the automatic refresh makes it redundant (user decision, 2026-09-24; Retry stays in ERR-01's error line). Offline "No internet connection · updated 5m ago". 36 pt plus a 1 pt hairline on top (WindowMetrics.bottomBarHeight), so its line meets the sidebar footer's and the terminal bar's as one line.
Kit
GitHubClient, pure PollSchedule: 30 s, or 15 s while checks or deployments run; nothing while the window cannot be seen. Tests: the two intervals, the stop and the immediate refresh when the window becomes visible.

Open menu

OPN-01

Open the workspace in an editor

In scope
Where
M2.5's Open menu (TB-03), right after "Finder": one item per installed editor, alphabetical: "Antigravity", "Cursor", "VS Code", "Zed". Then a divider, then New Terminal and Copy Path. (User request, relayed by dev-1.) The menu is 200 wide, with no path header and no "Open in" (user decision, 2026-09-24: "solo mostrar el logo del app y el nombre, como en conductor"). Picking an editor also makes it the default app (OPN-02).
Item
The app's own icon at 16 pt (NSWorkspace.shared.icon(forFile:) on the app's URL, as the menu's MenuItem icon) and the app's name. An editor that is not installed has no item; with none installed, the group and its divider are gone.
Detect
NSWorkspace.shared.urlForApplication(withBundleIdentifier:), checked when the menu opens (no caching, no polling): Antigravity com.google.antigravity-ide, Cursor com.todesktop.230313mzl4w4u92, VS Code com.microsoft.VSCode, Zed dev.zed.Zed.
Does
NSWorkspace.shared.open([worktreeURL], withApplicationAt: appURL, configuration:) on the worktree folder. A failure shows a toast with the error's description.
OPN-02

The default app

In scope
Why
User, 2026-09-24: "el archivo debe poder abrirse en el editor que se haya seleccionado por defecto arriba, así como en conductor que el path del documento, al darle clic abre el archivo en el editor seleccionado, en este caso, zed". Decisions (relayed by dev-1): the default is the last app picked in the Open menu ("el editor es el que está seleccionado arriba"), and there is one default for all of Rocky, not one per repository.
What
Finder or one of OPN-01's editors. It drives three things: the left part of the Open split button (M2.5 TB-03), ⌘O, and the path chip in the diff and file tab headers (M3 DIFF-01).
Set
Picking Finder or an editor in the Open menu opens the worktree there and makes it the default. New Terminal and Copy Path leave it as it is. There is no other setting for it.
First time
With nothing stored: the first installed editor in OPN-01's order, else Finder. The same fallback applies when the stored app is no longer installed; the stored value stays, so reinstalling the app brings it back. Resolved each time it is used (the menu opening, a click, ⌘O), as OPN-01 looks up the editors: no caching, no polling.
Stored
@AppStorage("defaultOpenApp"): the bundle id, com.apple.finder or the editor's. Not in the database: it is a preference of this Mac, like the folded repositories.
⌘O
File ▸ "Open in Zed" (the title follows the default; with Finder, "Open in Finder"), right after New Workspace (⌘N), in a CommandGroup(after: .newItem) next to NewWorkspaceCommand. It opens the selected workspace's worktree in the default app; it is disabled with no workspace selected. ⌘O is free: Rocky's File menu has no Open… (the app is a WindowGroup, with no documents), and no command in RockyApp.swift or shortcut in these specs uses it (checked 2026-09-24).
Opens a file
An editor: NSWorkspace.shared.open([fileURL], withApplicationAt: appURL, configuration:). Finder: NSWorkspace.shared.activateFileViewerSelecting([fileURL]), which reveals the file. A failure shows a toast with the error's description, as in OPN-01.
Kit
Pure DefaultOpenApp.resolve(stored: String?, installed: [ExternalEditor]) -> OpenApp (.finder or .editor(ExternalEditor)), next to ExternalEditor, with tests: nothing stored; an editor stored and installed; an editor stored but not installed; Finder stored; no editor installed.
Not known
Whether each editor opens the file in the window that already shows the worktree or in a new window; not checked for any of the four. To settle it: with the worktree open in the editor, click the chip. If an editor opens a new window, pass [worktreeURL, fileURL] together for that editor.
Done when
Pick Zed in the Open menu once: the split button shows Zed's icon, ⌘O opens the worktree in Zed, a diff tab's path chip has the tooltip "Open in Zed" and opens the file in Zed; after a relaunch the default is still Zed.
