Interactive spec. Everything in the window responds: hover, click, right-click, type in the search and the message box, press Run, open terminals, fold the panel (⌘J), drag both dividers, hold ⌘. Turn on Requirement pins and click any element to jump to its requirement on the right.

Pointing hand on everything clickable

In scope

Every element that does something on click shows the pointing hand: buttons, sidebar rows, repository headers, conversation, file and panel tabs, tab close buttons, the branch, menu items, file badges, the model button. Motion in the chat and everywhere

MOT-01

Rocky spinner replaces CircularProgress

In scope

A faint full ring with a quarter arc that turns smoothly. It replaces today's Material-style arc everywhere, in one place: the CircularProgress view.

Geometry
In a 16-unit box: ring radius 5.5, stroke 1.8, ring opacity 22 %; arc from 12 to 3 o'clock, round caps. Color: the current foreground. Sizes 14 (sidebar, default), 12 (tabs, folded headers, model menu), zoom-scaled.
Motion
One full turn every 0.9 s, linear, continuous, at the display's refresh rate. It must look fluid: never stepped, no jump at the loop (user decision, 2026-09-23). Frozen at its angle only while the window cannot be seen (NSWindow.occlusionState without .visible: minimized, hidden, fully covered or on another Space); it keeps turning while another app is active, since the user keeps Rocky visible beside other apps and a frozen spinner read as a stuck agent (user decision, 2026-09-24: "alive while visible"). Static with Reduce Motion.
SwiftUI
Rewrite CircularProgress.swift, keeping the type name and signature so its 7 call sites compile unchanged.
  • Not TimelineView(.animation) (today's code): it runs the body every display frame, once per spinner, against the energy goal (spec Section 1).
  • An NSViewRepresentable with two CAShapeLayers (ring, arc) and a CABasicAnimation on transform.rotation.z, 0 → 2π, 0.9 s, linear, repeatCount = .infinity. The render server interpolates; the app does no work per frame.
  • Pause with layer speed = 0 and timeOffset (resumes from the same angle) while the window is not visible (occlusionState), not merely inactive; no animation with Reduce Motion. Stroke colors from the environment in updateNSView.
  • Delete arc(at:) and easeInOut(_:).
Done when
Every spinner turns as smoothly as this one, and Time Profiler shows no per-frame work in Rocky while five spinners turn.
MOT-02

Message entrance

In scope

A message you send and every new row of the agent's turn fade in while rising 6 pt, instead of appearing at once. Try it: type in the message box and press Return.

Values
Opacity 0 → 1 and offset y 6 → 0 in 220 ms, curve (0.2, 0.7, 0.2, 1). Reduce Motion: opacity only, 150 ms.
Animate
Only rows created live while the conversation is on screen: the message just sent, the agent's text, thoughts and tool calls of the turn in progress, and the reply footer when the turn ends.
Never
  • History: rows from the store or replayed by session/load.
  • Switching tabs, workspaces, or coming back from a file tab.
  • LazyVStack re-creating rows while scrolling, so the trigger cannot be onAppear.
  • Each streamed chunk: the reply animates once, when its row first appears.
  • A lone tool row that becomes an "N tool calls" group (ChatRow.id changes from the item id to tools-<first id>).
SwiftUI
Each row gets an entrance key that survives regrouping: .item → its item id; .tools → its first item's id (the same key the lone row had); .turnFooter → "footer-" + summary.id. ChatView keeps settledKeys: Set<String>, filled with every key when the conversation appears; a row animates only if its key is not settled, and its key joins the set as it starts. Put ChatRow.entranceKey in RockyKit next to ChatLayout so the regrouping case has a unit test.
Done when
Opening a long conversation shows it at once; sending and the reply that follows animate; scrolling never replays an entrance.
MOT-03

Shimmer for live activity

In scope

While a tool runs or the agent works, the chat shows the activity's label with a light band sweeping across it, instead of a spinner. Try it: send a message and watch "Working" and "Run".

Where
ToolCallRow while live and pending or in progress; ToolGroupRow while live with a running call (its "N tool calls" title shimmers); ThinkingRow. These three stop using CircularProgress.
Working row
ThinkingRow today shows only the arc and the elapsed time. It becomes the word "Working", shimmering, followed by the elapsed time ("8s", "1m 5s"; monospaced digits, textTertiary, not shimmering). Not "Thinking": ThoughtRow already uses that label for the agent's thoughts. Consider renaming ThinkingRow to WorkingRow.
Values
Base textSecondary; a band 40 % of the text's width, peaking at textPrimary, sweeps left to right in 1.6 s linear, rests 0.5 s, repeats. When the call completes, the label settles to its normal color in 150 ms, same text and font, no layout change.
Rules
Paused only while the window cannot be seen (NSWindow.occlusionState without .visible: minimized, hidden, fully covered or on another Space), never just because another app is active ("alive while visible", 2026-09-24); static textSecondary with Reduce Motion; only live rows shimmer. Unread, the alert sound and the Dock badge still use "active" (the user is looking at Rocky).
SwiftUI
New ShimmerText: the Text in textSecondary, overlaid by the same Text in textPrimary masked by a moving LinearGradient, driven by TimelineView(.animation(minimumInterval: 1.0 / 30, paused: …)).

Keyboard and accessibility

KBD-01

Keyboard

In scope
New
  • ↑ / ↓ with the list focused: move through visible rows (folded repositories skipped).
  • ⌘1 … ⌘9: select the 1st … 9th visible workspace, from anywhere.
  • ⌘N: new workspace in the selected workspace's repository (first repository if none; disabled with none).
  • ⌘K: focus the search. Esc: clear it.
  • Holding ⌘ for 400 ms shows "⌘1" … "⌘9" in the rows. Try it here (the browser keeps ⌘1–9 for its own tabs).
Existing, keep
⌘J fold the panel · ⌘U attach · ⇧Tab plan mode · ⌘, settings · ⌘+ ⌘- ⌘0 zoom. None of the new shortcuts collides with them.
Focus ring
Keyboard focus only: 2 pt accent ring inside the element's radius.
SwiftUI
⌘1–⌘9, ⌘N and ⌘K as menu commands in RockyApp. ⌘N through CommandGroup(replacing: .newItem): without it, ⌘N opens a second window (the app is a WindowGroup). Arrows: .focusable() + .onKeyPress. ⌘ hold: a local NSEvent monitor for .flagsChanged.
