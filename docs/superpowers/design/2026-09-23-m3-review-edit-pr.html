Rocky · Review and edit (M3)

Interactive spec on top of M2.5's shell and M2.7's right panel. Open a file from the Changes tab, hover a line and click + (or drag across line numbers) to comment, Send to agent, switch to Edit and type (⌘S saves), Commit…. The panel's header and its Checks tab are M2.7's, drawn simplified; the pull request lives there.

Git

GIT-01

Finding what changed

In scope
Base
git merge-base <baseRef> HEAD. baseRef is workspace.baseRef; when nil (workspaces made by M1), origin/HEAD's branch; else the repository's current branch.
Diff
git diff --no-color --no-ext-diff --find-renames -U3 <base>: committed, staged and unstaged changes against the base. Plus untracked files from git ls-files --others --exclude-standard -z, read directly and shown as added (binary or over 1 MB: DIFF-03). Uncommitted paths from git status --porcelain=v1 -z.
When
FSEvents on the worktree and on its git directory (the worktree's .git file points to <repo>/.git/worktrees/<name>), excluding node_modules and .git/objects, 500 ms debounce. Skip while a rebase or merge is in progress (rebase-merge, rebase-apply, MERGE_HEAD) or index.lock exists, and retry on the next event.
Energy
Every workspace keeps an FSEvents stream (no process). On a change: the sidebar's shortstat only. The full diff only for the selected workspace while its Changes tab is visible. At rest: no processes (spec Section 1).
Kit
GitChangesService (actor) and FileWatcher (FSEventStream) in RockyKit; AppModel.changes[workspaceId], git run with ProcessRunner in the worktree.
Done when
Tests on temporary repositories: modified, added, untracked, deleted, renamed, binary; a base that moved after the branch was created; a workspace with nil baseRef.
GIT-02

Parsing the diff

In scope
Kit
Pure DiffParser.parse(_ output: String) -> [FileDiff]: path, old path (renames), status (added, modified, deleted, renamed), binary flag, mode change, hunks (header, old and new start and count, lines with kind and old/new numbers), "no newline at end of file" per side.
Done when
Fixture tests: each status, \ No newline at end of file, Binary files … differ, a rename with similarity, a mode-only change, several hunks.
GIT-03

Diff stats in the sidebar rows

In scope

M2.5's OUT-01, now in scope because GIT-01 exists. Values unchanged: +A −D, 11 mono tabular, success / #E48A8A, thousands as "2.3k", hidden on hover and while ⌘ is held. Source: git diff --shortstat <base> plus untracked lines.

GIT-04

Commit

In scope
Entry
"Commit…" in the Uncommitted section header of the Changes tab.
Why
Commits without the agent, typically your own edits from the editor. M2.7's "Commit and push" (AGT-02) asks the agent instead.
Sheet
500 wide, slides from the top of the window in 200 ms. Title "Commit changes"; the uncommitted files (status letter and path, read-only); subject (prefilled with the workspace title, 72-character counter that turns attention past 72); optional description; Cancel / Commit (⌘Return; disabled with an empty subject).
Does
git add -A then git commit -m <subject> [-m <description>] in the worktree with the workspace environment. Hook output shows in the sheet while it runs; on failure the sheet stays open with the output and the exit code. Git's own identity settings apply (M4 injects the account's).
GIT-05

Discard a file's uncommitted changes

In scope
Entry
File row hover action (arrow.uturn.backward) and the diff tab's "⋯" menu, for uncommitted files only.
Does
Confirmation "Discard changes to openapi.ts? This cannot be undone." Tracked files: git restore --staged --worktree -- <path>. Untracked files: moved to the Trash (NSWorkspace.recycle), not deleted. Its diff tab closes. Committed changes are never discarded from Rocky.

Changes tab

CHG-01

The Changes tab

In scope
Layout
A tab in M2.7's tab row (PNL-03), before Checks: "Changes" + the number of changed files (11 mono textTertiary; hidden when 0). M2.7's pill style: 26 pt, radius 6, selected fillSelected.
Behavior
Selecting it shows CHG-02. ⌘⇧C shows the right panel on this tab; pressed again while this tab shows, it hides the panel. The selected tab is remembered per workspace (PNL-03). The top bar keeps M2.7's toggle (PNL-02); M3 adds no top bar control.
Replaces
M3's former top bar toggle and its own panel (changesPanelOpen, changesPanelWidth): the panel's width, divider and open state are M2.7's (PNL-01).
CHG-02

Tab layout

In scope
Above
M2.7's panel header (HDR-01) and tab row stay above the tab; nothing of M3 goes there.
Parts
A 30 pt row: "5 files" (12 textSecondary), the total +A −D, spacer, "⋯" (Refresh, Discard All Uncommitted Changes…). Then the file list (scrolls). Then the comments bar (CMT-05), pinned at the bottom while pending comments exist.
CHG-03

File rows

In scope
Sections
"Uncommitted" (files with changes not yet committed, with "Commit…" on the right) and "Committed" (changed on this branch, already committed). 10.5 uppercase textTertiary headers with a count. A file with both kinds of change sits in Uncommitted.
Row
28 pt, radius 7: status letter (A success, M attention, D danger, R textSecondary; 11 mono semibold), file name 13, directory 11 textTertiary (truncated at its start), then the comment count (bubble + n) and +a −d. Hover: Edit (pencil) and, for uncommitted files, Discard replace the counts. Selected (its diff tab is active): fillSelected.
Behavior
Click opens the file's diff tab or selects it if open. ⌥⌘↓ / ⌥⌘↑ go to the next / previous file.
Empty
"No changes yet" and "Changes the agent makes in this workspace show up here."

Diff

DIFF-01

Diff tab

In scope
Tab
After conversations and files in the tab row (M2.5 TAB-01). Status letter instead of the file icon, then the file name; tooltip: the path. Unsaved edits: a 7 pt dot replaces the close button until hover. One tab per file.
Header
34 pt: directory (textTertiary) + name 12.5, +a −d, then "Edited" and Save while there are unsaved edits, a segmented control Diff | Edit (24 pt, fillControl, selected fillSelected), and "⋯" (Open in Finder, Copy Path, Discard Changes…).
Closing
With unsaved edits: "Save changes to openapi.ts?" Save / Don't Save / Cancel.
DIFF-02

Unified diff

In scope
Rows
12 mono, 20 pt rows. Old number and new number columns (40 each, right-aligned, textTertiary), a 16 pt marker column (+ / −), then the code with syntax colors (DIFF-04). Added rows: diffAddLine, their gutter diffAddGutter, marker success. Removed: the delete tokens and danger. Context: no fill.
Hunks
Header row 26 pt, "@@ -40,7 +40,12 @@" 11.5 mono textTertiary on diffHunk. Three context lines around changes. Unchanged runs between hunks collapse to a 26 pt row "⋯ 18 unchanged lines" that expands on click.
Other
No wrapping: long lines scroll horizontally, the number columns stay. Text inside a row is selectable for copying.
SwiftUI
A LazyVStack of rows (so comment cards can sit between rows), one row per line. It is read-only: editing is the Edit mode (EDIT-01), not the diff.
Done when
A 2,000-line diff scrolls smoothly; beyond DIFF-03's limit it stays collapsed.

DIFF-04

Syntax highlighting

In scope
Kit
Prism, vendored as a resource of RockyUI and run in JavaScriptCore, the same approach Textual uses internally (its CodeTokenizer is not public, so it cannot be reused). Language from the file extension; unknown → plain text. Token types map to Theme.syntax (TOK-10).
Rules
Tokenize off the main thread; show plain text until tokens arrive; cache per file content hash. The editor re-tokenizes 150 ms after typing stops.
DIFF-05

From the chat

In scope

A tool call's file badge (Read, Edit…) for a file that is in Changes opens its diff tab, scrolled to the first hunk; other files open the plain file tab as today. This is the "see what the agent changed" M2 left a place for. Try it: the "openapi.ts" badge in the conversation.

Comments

CMT-01

Selecting lines

In scope
Behavior
Hovering a row shows a 16 pt "+" (accent fill, dark glyph, radius 4) over its new line number (old number for removed rows). Click: comment on that line. Drag from "+" or a line number: a range. Shift-click another line number: a range from the last one clicked. A range stays on one side: new-side lines (added and context) or old-side lines (removed). Esc clears.
Values
Selected rows: commentRange fill and a 3 pt accent bar at their left edge.
CMT-02

Composer and comment cards

In scope
Composer
Under the last selected line, aligned with the code: "Comment on line 14" or "lines 14–22" (11.5, textSecondary), a text box (13, 3 lines min), a hint "⌘Return to comment", Cancel and Comment (white filled). Esc cancels when empty; with text it asks first.
Card
Under its range: "You", relative time, a state chip, Edit and Delete on hover, the text (13). Chips: Pending (attention outline), Sent (textSecondary, check), Outdated (textTertiary, tooltip "The commented lines changed").
CMT-03

Storage

In scope
Store
The next free migration, table diffComment: id, workspaceId, path, side ('new' | 'old'), startLine, endLine, snippet, contextBefore, contextAfter, body, state ('pending' | 'sent' | 'outdated'), createdAt, sentAt. Comments survive a relaunch; removing a workspace removes its comments.
CMT-04

Keeping comments on their lines

In scope
Rule
After every diff refresh, for each new-side comment: the snippet still at its lines → stays; else the snippet found elsewhere → moves to the match nearest its old position; else → Outdated (keeps its text and last lines). Old-side comments only need the base, which does not change. Outdated comments sit at the top of the file's diff in a collapsed "2 outdated comments".
Kit
Pure CommentAnchor.relocate(comment:newText:) -> LineRange?. Tests: unchanged; shifted by lines inserted above; edited inside → nil; snippet appears twice → nearest wins.
Try it
Comment on lines of operation() in openapi.ts, then "Agent edits openapi.ts on disk".
CMT-05

Send to agent

In scope
Entry
The comments bar pinned at the bottom of the Changes tab: "2 comments ready" and Send to agent (white filled), while pending comments exist. Disabled with "The agent is working" while a turn runs.
Does
One prompt to the workspace's selected conversation (its agent starts if needed); the tab switches to that conversation; the comments become Sent. The prompt:
Review comments on jhzl/openapi-export:

1. src/openapi.ts, lines 18–25
```ts
function operation(route: Route) {
  …
```
Use the route's name as operationId only when it is unique.

2. …

Address each comment and say what you changed for each number.
Kit
Pure ReviewPrompt.build(branch:comments:fileTexts:) with a test for the exact text.

Editor

EDIT-01

Code editor

In scope
Where
The Edit mode of a diff tab, and file tabs of code, data and text files (today's FileTabView shows those read-only). Markdown file tabs get Preview | Edit. Images, PDFs and Quick Look files stay as they are; files over 2 MB stay read-only.
Features
12.5 mono, 20 pt lines; gutter with line numbers (textTertiary, current line textPrimary) and change bars (EDIT-04); currentLine fill; syntax colors (DIFF-04); undo and redo; the system find bar (⌘F); go to line (⌘L); Tab inserts the file's indentation (detected: spaces or tab); no wrapping, no autocorrect, smart quotes or spell check.
SwiftUI
CodeEditor: an NSViewRepresentable around an NSTextView in an NSScrollView with a ruler view for the gutter (NSRulerView subclass), usesFindBar = true, isAutomaticQuoteSubstitutionEnabled = false and the other substitutions off.
Done when
Editing a 5,000-line file keeps typing responsive; undo goes back past a save.
EDIT-02

Saving

In scope
Behavior
⌘S or Save writes the file atomically, keeping its line endings and final newline. Unsaved: tab dot, "Edited" and Save in the header. Back in Diff mode with unsaved edits: the diff of the saved file and a banner "Unsaved edits · Save to see them here". After saving, the diff and the change bars refresh.
EDIT-03

When the file changes on disk

In scope
Clean buffer
Reload in place, keeping the caret line and scroll; the header shows "Reloaded" for 2 s.
Unsaved edits
Banner "This file changed on disk." with Reload (drops your edits) and Keep Mine (your next save overwrites it). Saving compares the file's modification date and content hash with the loaded ones; if they differ and Keep Mine was not chosen, it shows the banner instead of writing.
Agent working
While the workspace's agent runs a turn: banner "Claude Code is working in this workspace and may change this file." with a close button (per tab).
Try it
Edit openapi.ts without saving, then "Agent edits openapi.ts on disk".
EDIT-04

Change bars

In scope

3 pt bars left of the line numbers, against the base: added success, modified attention, a small danger triangle where lines were removed. They follow the buffer as you type.

Errors and keyboard

ERR-02

Git errors

In scope

A git failure (diff, commit, discard) shows where the action was, the sheet or the Changes tab, with the last lines of its stderr. GitHub errors are M2.7's ERR-01.

KBD-02

Keyboard
