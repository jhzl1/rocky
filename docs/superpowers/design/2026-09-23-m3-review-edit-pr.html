Rocky · Review and edit (M3)

Interactive spec on top of M2.5's shell and M2.7's layout and right panel. Browse the worktree in All files (click opens a preview tab, double-click keeps it). ⌘P opens Quick Open, the file finder over everything (the "Quick Open" demo button does the same, since the browser prints on ⌘P). Open a file from the Changes tab, hover a line and click + (or drag across line numbers) to comment and send it at once to a conversation, switch to Edit and type (⌘S saves), Commit…. The panel's header and its Checks tab are M2.7's, drawn simplified; the pull request lives there.

Git

GIT-01

Finding what changed

In scope
Base
git merge-base <baseRef> HEAD. baseRef is workspace.baseRef; when nil (workspaces made by M1), origin/HEAD's branch; else the repository's current branch.
Diff
git diff --no-color --no-ext-diff --find-renames -U3 <base>: committed, staged and unstaged changes against the base. Plus untracked files from git ls-files --others --exclude-standard -z, read directly and shown as added (binary or over 1 MB: DIFF-03). Uncommitted paths from git status --porcelain=v1 -z.
When
FSEvents on the worktree and on its git directory (the worktree's .git file points to <repo>/.git/worktrees/<name>), excluding node_modules and .git/objects, 500 ms debounce. Skip while a rebase or merge is in progress (rebase-merge, rebase-apply, MERGE_HEAD) or index.lock exists, and retry on the next event.
Energy
Every workspace keeps an FSEvents stream (no process). On a change: the sidebar's shortstat only. The full diff only for the selected workspace while its Changes tab is visible. At rest: no processes (spec Section 1).
Kit
GitChangesService (actor) and FileWatcher (FSEventStream) in RockyKit; AppModel.changes[workspaceId], git run with ProcessRunner in the worktree.
Done when
Tests on temporary repositories: modified, added, untracked, deleted, renamed, binary; a base that moved after the branch was created; a workspace with nil baseRef.
GIT-02

Parsing the diff

In scope
Kit
Pure DiffParser.parse(_ output: String) -> [FileDiff]: path, old path (renames), status (added, modified, deleted, renamed), binary flag, mode change, hunks (header, old and new start and count, lines with kind and old/new numbers), "no newline at end of file" per side.
Done when
Fixture tests: each status, \ No newline at end of file, Binary files … differ, a rename with similarity, a mode-only change, several hunks.

GIT-04

Commit

In scope
Entry
"Commit…" in the Uncommitted section header of the Changes tab.
Why
Commits without the agent, typically your own edits from the editor. M2.7's "Commit and push" (AGT-02) asks the agent instead.
Sheet
500 wide, slides from the top of the window in 200 ms. Title "Commit changes"; the uncommitted files (status letter and path, read-only); subject (prefilled with the workspace title, 72-character counter that turns attention past 72); optional description; Cancel / Commit (⌘Return; disabled with an empty subject).
Does
git add -A then git commit -m <subject> [-m <description>] in the worktree with the workspace environment. Hook output shows in the sheet while it runs; on failure the sheet stays open with the output and the exit code. Git's own identity settings apply (M4 injects the account's).
GIT-05

Discard a file's uncommitted changes

In scope
Entry
File row hover action (arrow.uturn.backward) and the diff tab's "⋯" menu, for uncommitted files only.
Does
Confirmation "Discard changes to openapi.ts? This cannot be undone." Tracked files: git restore --staged --worktree -- <path>. Untracked files: moved to the Trash (NSWorkspace.recycle), not deleted. Its diff tab closes. Committed changes are never discarded from Rocky.

In scope

FIL-04

Filter and Go to File

In scope
Filter
Typing replaces the tree with a flat list of matching files: icon, name, directory (11 textTertiary), status letter. Matching is case-insensitive over the relative path, ranked: the name starts with the query; the name contains it; the path contains it; the query's characters appear in order in the name ("srv" finds server.ts); then in order anywhere in the path. Ties in Finder's order. Matched characters are drawn in accent. Empty query: the tree comes back as it was.
Keys
↓ / ↑ move through the results, Return opens (FIL-05), Esc clears the query and a second Esc leaves the field.
Scope
This is the All files tab's own filter, and it stays. Finding a file from anywhere is Quick Open (FIL-08, ⌘P).
Source
The file list comes from git ls-files --cached --others --exclude-standard -z in the worktree (tracked and untracked, ignored ones left out), so the filter needs no directory walk.

FIL-09

File icons (Material Icon Theme)

In scope
Why
User, 2026-09-24: "los files no tienen sus íconos… por cada tipo de archivo, tener un ícono… fijarte en algún tema de vsc". Every code file showed the same </> and every data file the same {}. User decision: Material Icon Theme, files only; folders keep today's blue folder.
Source
npm material-icon-theme 5.38.1 (MIT, © 2025 Material Extensions), pinned like Prism. Its dist/material-icons.json maps 2,135 fileNames (204 of them path tails such as .config/graphqlrc) and 1,377 fileExtensions to icon ids; the default is file.
Ships
The 587 icons (493,218 bytes of SVG): the 586 that fileNames, fileExtensions and the default reference, plus github-actions-workflow, which only languageIds reaches and the vendoring script adds for the workflow rule below. Also a trimmed manifest with just those two maps and the default, as RockyUI resources. Not shipped: the 542 folder icons, the 48 light variants (Rocky is dark), the other 8 icons reached only through VS Code languageIds. (Counts from the implementation, dev-1, 2026-09-24.)
Lookup
Case-insensitive, first match wins: (1) the one emulated languageIds rule: a .yml / .yaml at any depth under .github/workflows/ gets github-actions-workflow; it is checked first, or yml → yaml would always win; (2) the longest path tail in fileNames (.config/graphqlrc); (3) the file name (package.json → nodejs, tsconfig.json → tsconfig, .gitignore → git, README.md → readme); (4) the extensions, in one pass over the name after each dot, longest first, as VS Code does: test.ts → test-ts before ts → typescript, d.ts, tsx → react_ts, yml → yaml, and .env → env → tune; (5) the default file icon. FileKind's SF Symbol is only the fallback if an SVG fails to load.
Where
Everywhere a file's icon is drawn: the All files tree, Quick Open, Changes rows (after the status letter), unchanged file tabs (changed ones keep their status letter, DIFF-01), the diff and file tab headers, the chat's file badges and the composer's attachments (FileBadge), the line chip (CMT-06), tabs of files outside the worktree, and the file hover preview card.
Size
14 pt in 26–28 pt rows and headers (tree, Quick Open, Changes, tab headers); 12 pt in 22 pt elements (tabs, including those of files outside the worktree, badges, the chip); 22 pt in the hover preview card. The SVGs come in 16, 24, 32, 300 and 1024 viewBoxes; they are drawn scaled to the size, never as bitmaps.
Dimmed
Ignored files (FIL-03) draw their icon at 50 %, like their name.
Code
A FileIcons lookup in RockyKit (pure: path → icon id, with tests for each step and the workflow rule) and a view in RockyUI that loads the SVG the way Rocky's other bundled SVG marks load, cached per id. The icons are decorative for VoiceOver; the name carries the meaning.
License
The package's LICENSE is copied next to the icons, and README.md credits Material Icon Theme, as it does Prism and Simple Icons.

FIL-07

Energy and big repositories

Technical
Watch
The worktree's FSEvents stream from GIT-01, no second stream and no polling. An event for a path invalidates only its folder's listing.
Lazy
Only expanded folders are read (FileManager.contentsOfDirectory when a folder opens, cached until an event for it). A collapsed folder costs nothing, so a repository with 100,000 files opens as fast as a small one.
Ignored
Classified with the ls-files list of FIL-04: an entry that is neither listed nor the parent of a listed path is ignored. ls-files runs once when the tab first shows and again after events, debounced 500 ms, only while the tab is visible; never on a timer.
Kit
Pure FileTree (build rows from listings, expanded set, ignored set; sort; filter ranking) with tests: order, the ignored rule, a filter tie, a deleted file absent, 100,000 paths ranked in under 50 ms.

DIFF-06

Line counts on edit rows

In scope
Why
User, 2026-09-25 (relayed by dev-1): "en las ediciones a los archivos, sería bueno también ver cuántas líneas quitó y agregó". Like Conductor. Today the row reads "Edit [README.md]" with no counts.
Row
After the tool row's file badges, gap 6: DiffStatLabel as in Changes ("+2 −1", 11 mono, success / diffDeletions, tabular, abbreviated as in Changes). Both numbers show, "+10 −0" included; nothing when both are 0 or the counts are unknown. VoiceOver: the label's own "2 lines added, 1 removed".
Which rows
Any tool call whose content holds ACP diff entries ({type: "diff", path, oldText, newText}), whatever its kind or title: Claude's Edit, MultiEdit and Write; OpenCode's edit, write and patch. One label per call: the sum over its entries, also when they touch several files.
When
Only while the call's status is completed, with the counts of its latest content. Pending, in progress, failed or rejected: no label, since the file has not changed. Claude's first tool_call carries an optimistic diff (a Write looks like a new file), and the update after the tool runs replaces it with the real hunks. An update that carries content replaces the counts, as ACP replaces the content; one without content keeps them.
Group
The "N tool calls" group header shows the same label after its title: the sum of its rows' labels, hidden at 0. It is what the rows say, not the files' net change, so a line edited twice counts twice. (dev-2's call, 2026-09-25: a folded group would otherwise hide the counts; the user can drop it.)
Counting
Per entry, first match: (1) Claude's stats, _meta.jetbrains.air.diffStats with version 1: added, removed (claude-agent-acp 0.81.0 dist/diff.js puts them on each hunk entry whose coordinates check out); (2) oldText null (a new file, or a hunk that only adds): added is newText's line count; (3) a line diff of oldText against newText with CollectionDifference: insertions are added, removals removed. Claude's hunks include context lines; the diff drops them, since they sit on both sides. Lines split on "\n"; the empty piece after a final newline is not a line, and empty text has 0 lines.
Cap
Step 3 runs off the main actor and only when both sides together have at most 5,000 lines. Over it the entry has no counts, and a call with any entry it cannot count shows no label: a partial sum would be wrong. The case is a whole-file Write of a large file (Claude sends originalFile and the new content when its patch comes back empty; when the old file was too large to diff it sends text instead, which has no counts).
Stored
On the tool call's transcript row, so resumed conversations keep it: additions and deletions, nullable integers on chatMessage, by the next free migration. Rows saved before it have nil and show no label.
Kit
ACP: ACPUpdate.toolCall / toolCallUpdate gain diffs: [ToolCallDiff]? (path, oldText, newText, and the stats when _meta has them): nil when the update has no content, empty when its content has no diffs. Pure ToolDiffStats.count(_:) -> DiffStat? with tests: Claude's stats used as sent; a new file; context lines not counted; a final newline; over the cap; one uncountable entry makes it nil. ChatItem gains diffStat: DiffStat?; ChatSessionModel tests: counts appear on completion, not before; an update with content replaces them, one without keeps them; failed shows none.
Done when
Claude edits two lines in README.md: the row reads "Edit [README.md] +1 −1" once the edit completes, the folded group shows the same, and relaunching Rocky keeps it.

CMT-02

The comment box

In scope
Opens

The picker is Rocky's menu: the workspace's open conversations, a check on the chosen one. Default: the conversation last shown in this workspace.
Body
The line chip (CMT-06) fixed at the start, then the text, 13 pt, 22 pt lines, at least two lines, growing; placeholder "Ask about these lines…". The chip cannot be deleted; Cancel drops the whole comment.
Actions
"⌘Return to send" (11.5 textTertiary), Cancel, and Send (white filled; disabled while the text is empty). While the chosen conversation's turn runs, Send reads "Queue" with the tooltip "Claude Code is working; this goes out when its turn ends" (CMT-05).
Keys
⌘Return sends; Return is a new line; Esc closes an empty box, and with text asks "Discard this comment?" first. A draft lives in memory while its file tab is open, and switching tabs keeps it.
CMT-05

Sending a comment

In scope
Does
Send posts one message to the chosen conversation right away (its agent starts if needed). The agent's text (below) is built at Send, with the lines' code as it is then. The diff stays on screen and the box closes; a toast says "Sent to “Review the schemas”" with Show, which opens that conversation (a toast with an action stays 4 s).
Running
If that conversation's turn is running, the message goes into its M2.5 queue as a queued row (the chip and the text) with Send now, Edit and Remove. Edit brings the chip and the text back into the message box, as ↑ does (History), and drops the captured code, so the next Send reads the lines again (Resend). Edit is offered while the box is empty, like any queued row's (M2.5). (Edit was left out while the box could not hold a chip; dev-2 puts it back, 2026-09-25, and the user can drop it.) It keeps the code captured at Send, so edits the agent makes during its turn do not change it. The toast says "Queued in “Review the schemas”", with Show.
History
↑ on a line-comment message brings back its chip (CMT-06) at the start of the message box, with the comment after it (user decision, 2026-09-25: "Chip y texto"; before, the history skipped these messages and ↑ landed on an older one). The box holds one chip at most, and only ↑ and a queued row's Edit put one there. Backspace at the start of the text removes it, and the message then goes as a normal one. With the chip first, a "/" at the start of the text is not a command (CMD-01). Review prompts sent before this redesign are plain text in the transcript, and ↑ brings them back as they are.
Resend
Sending from the box with the chip builds the agent's block again, at Send. New side: the worktree file's lines. Removed side: the base's lines, read with git cat-file as the diff reads the base. The range is the chip's, so the code is what those lines hold now, which may differ from the first send. If any line cannot be read (the file is gone, or the range runs past its end), the block goes without code: "Comment on src/openapi.ts, lines 18–25:" (removed side: "Comment on src/openapi.ts, removed lines 12–13 (from the base):"), then the comment. During a turn it queues as above (Running), and it is stored like the first send (Stored).
Transcript
The user message shows the chip and the text only (CMT-06), not the prompt.
Agent
The agent receives the lines' code with the comment, as one text block:
Comment on src/openapi.ts, lines 18–25:
```ts
function operation(route: Route) {
  …
```
Use the route's name as operationId only when it is unique.
Removed lines
"Comment on src/openapi.ts, removed lines 12–13 (from the base):", with the base's code.
Stored
No new table: the message's text is the comment, and the chip is one entry of the message's existing attachments array, an absolute path plus a fragment like every chat attachment, /…/tokyo/src/openapi.ts#L18-25 (removed side …#base-L12-13). The agent's text uses the worktree-relative path. When the prompt is built, that entry becomes the text block above instead of a resource_link. The diffComment table from the first M3 build is dropped by the next free migration (its v9 stays registered as history).
Kit
Pure ReviewPrompt.single(path:side:start:end:code:language:comment:) with tests for the exact text on each side; code is optional, and nil gives the block without code, with a test on each side. History entries of line-comment messages carry their LineRangeAttachment, with a MessageHistory test that ↑ stops on them; LineRangeAttachment parses and prints the #L form. CommentAnchor and DiffCommentRecord are gone.
CMT-06

The line chip

In scope
Look
Conductor's: 22 pt, radius 6, a 1 pt hairline border on white 4 %; a 22 pt left segment with the file's icon (FIL-09, 12 pt) and a hairline divider; then the file name (12 textPrimary) and the range (12 textSecondary, tabular): "+18–25" for new-side lines, "−12–13" for removed ones, "+18" for one line.
In the box
At the start of the text, before the caret, not editable; the caret cannot go before it. In the comment box it cannot be deleted either: the box exists for that range. In the message box, where ↑ and a queued row's Edit bring it back (CMT-05 History), Backspace at the start of the text removes it, like any attachment there. Copy and paste leave it out, so it never appears twice or in the middle of the text.
In the transcript
At the top of the user message, the text under it. A click resolves the path like a file badge and opens the file's diff tab scrolled to those lines (if the file is no longer changed, its file tab). Tooltip: the path and the range.

Editor

EDIT-01

Code editor

In scope
Where
The Edit mode of a diff tab, and file tabs of code, data and text files (today's FileTabView shows those read-only). Markdown file tabs get Preview | Edit. Images, PDFs and Quick Look files stay as they are; files over 2 MB stay read-only.
Features
12.5 mono, 20 pt lines; gutter with line numbers (textTertiary, current line textPrimary) and change bars (EDIT-04); currentLine fill; syntax colors (DIFF-04); undo and redo; the system find bar (⌘F); go to line (⌘L); Tab inserts the file's indentation (detected: spaces or tab); no wrapping, no autocorrect, smart quotes or spell check.
SwiftUI
CodeEditor: an NSViewRepresentable around an NSTextView in an NSScrollView with a ruler view for the gutter (NSRulerView subclass), usesFindBar = true, isAutomaticQuoteSubstitutionEnabled = false and the other substitutions off.
Done when
Editing a 5,000-line file keeps typing responsive; undo goes back past a save.
EDIT-02

Saving

In scope
Behavior
⌘S or Save writes the file atomically, keeping its line endings and final newline. Unsaved: tab dot, "Edited" and Save in the header. Back in Diff mode with unsaved edits: the diff of the saved file and a banner "Unsaved edits · Save to see them here". After saving, the diff and the change bars refresh.
EDIT-03

When the file changes on disk

In scope
Clean buffer
Reload in place, keeping the caret line and scroll; the header shows "Reloaded" for 2 s.
Unsaved edits
Banner "This file changed on disk." with Reload (drops your edits) and Keep Mine (your next save overwrites it). Saving compares the file's modification date and content hash with the loaded ones; if they differ and Keep Mine was not chosen, it shows the banner instead of writing.
Agent working
While the workspace's agent runs a turn: banner "Claude Code is working in this workspace and may change this file." with a close button (per tab).
Try it
Edit openapi.ts without saving, then "Agent edits openapi.ts on disk".
EDIT-04

Change bars

In scope

3 pt bars left of the line numbers, against the base: added success, modified attention, a small danger triangle where lines were removed. They follow the buffer as you type.

Errors and keyboard

ERR-02

Git errors

In scope

A git failure (diff, commit, discard) shows where the action was, the sheet or the Changes tab, with the last lines of its stderr. GitHub errors are M2.7's ERR-01.

KBD-02

Keyboard
